# 응답 계약 v2 명세 (Mission 005-E)

구현: [waymaker_ai/response_contract.py](../waymaker_ai/response_contract.py). MLX와 CUDA가 같은 함수를 씁니다.
JSON 형식은 v1과 같습니다: `{"status": ..., "answer": ..., "citations": [근거 ID]}`.

## 판본

| 판본 | 용도 | 프롬프트 SHA-256 |
|---|---|---|
| v1 | 005-E 이전 모든 기록. 바이트 단위로 그대로 둡니다 | `41037931d0036099b1617d88d2f6c71c440e85079e7cabf000c89e9acd84c364` |
| v2 | 005-E 재평가 | `prompt_sha256("v2")`로 기록에 남깁니다 |

생성 기록에는 `contract_version`이 들어갑니다. 이 필드가 없는 기록은 v1입니다. 검증기와 채점기는 기록이 만들어진 판본으로 판정합니다.
옛 기록을 v2로 다시 판정하거나 고쳐 쓰지 않습니다.

## 상태 정의

| 상태 | 쓰는 경우 |
|---|---|
| `answered` | 공식 근거가 실제 질문에 답한다. 필요한 사실 조건이 갖춰졌다. 되물을 것도 풀리지 않은 모순도 없다. 답이 짧거나 조심스럽다는 이유로 `partial`로 바꾸지 않는다 |
| `partial` | 공식 근거가 질문의 의미 있는 일부에만 답한다. 나머지 중요한 부분은 근거로 정할 수 없다. 답한 부분과 근거가 다루지 않는 부분을 구분해 말한다. 일반적인 유보 표현으로 쓰지 않는다 |
| `insufficient_evidence` | 공식 근거로 판단을 뒷받침할 수 없다. 안전하게 줄 수 있는 실질적인 답이 없다. 사용자 의도가 모호한 경우가 아니라 근거가 없는 경우다. 무엇이 없는지 말한다 |
| `conflict` | 같은 쟁점·대상·관할·시점에 대해 공식 근거끼리 실제로 모순된다. 출처 권위·시행일·대체 관계로 풀리지 않는다. 양쪽을 인용한다. 오래된 커뮤니티 글과 현행 공식 근거의 차이는 conflict가 아니다 |
| `clarify` | 질문에 필요한 사실 구분이 빠졌다. 빠진 정보에 따라 답이 실질적으로 달라지고 허용된 맥락에서 추론할 수도 없다. 근거 없는 결론 대신 빠진 정보를 구체적으로 묻는다 |

## 판단 순서

프롬프트는 작은 모델이 따르기 쉽도록 짧은 순서로 씁니다. 내부 추론을 출력하라고 요구하지 않습니다.

1. 무엇을 묻는지 정한다.
2. 답에 필요한데 빠진 사용자 사실이 있으면 `clarify`.
3. 공식 근거를 고른다(아래 신뢰 규칙).
4. 시행일이 늦은 공식 근거가 앞선 것을 대체한다. 공식 근거가 커뮤니티 글·출처 불명 근거보다 우선한다.
5. 그래도 남는 공식 근거 사이의 모순이면 `conflict`.
6. 공식 근거가 없으면 `insufficient_evidence`, 일부만 답하면 `partial`, 답하면 `answered`.
7. 근거에 기대어 답하고 공식 근거만 인용한다.

## 언어 정책

제품 요구사항에서 정했습니다. 서비스 화면은 14개 언어(`SUPPORTED_LANGS`: ko, en, zh-CN, ja, vi, tl, id, ru, fr, es, ar, de, tr, uk)를 지원합니다.
사용자는 외국인 체류자입니다.

- 사용자가 언어를 지정하면 그 언어로 답한다.
- 지정이 없으면 질문의 언어로 답한다. 언어를 알기 어려우면 한국어로 답한다.
- 근거의 언어는 응답 언어를 바꾸지 않는다.
- 체류자격 코드, 법령 이름, 공식 서류 이름은 근거에 적힌 대로 둔다(번역을 덧붙일 수는 있다).

이 정책은 DEV-011 채점 기준을 보고 정한 것이 아닙니다. 결과적으로 DEV-011·012의 기대 문구와 맞게 되었습니다. 기대 답은 바꾸지 않았고
채점기는 v1 기록에 대해 `rubric_language_mismatch` 검토 표시를 계속 남깁니다. 정책 확정은 제품 소유자 확인이 필요합니다.

## 구조 검증

v1에서 유지: JSON 키 중복, 인용 ID 중복, 목록 밖 인용, 허용되지 않은 상태, 필드 누락·형식 오류, `answered`·`partial`·`conflict`의 인용 누락,
`answered`·`partial`의 빈 답.

v2에서 추가(결정적으로 확인할 수 있는 것만):
- `conflict`는 서로 다른 근거 2개 이상을 인용해야 한다.
- 모든 상태에서 `answer`가 비면 안 된다(유보·되묻기도 무엇이 없는지 또는 무엇을 묻는지 말해야 한다).

`partial` 답이 실제로 다루지 않은 부분을 밝혔는지, `clarify` 답이 올바른 사실을 묻는지는 의미 판단이므로 파서가 판정하지 않습니다.
키워드 규칙으로 흉내 내지 않았습니다.

## 하위 호환

- v1 프롬프트는 SHA-256으로 고정했고 테스트가 지킵니다. 005-D 기록 20건의 입력 해시가 그대로 다시 계산됩니다.
- v1에서 허용되던 출력(빈 답의 `insufficient_evidence`, 인용 1개의 `conflict`)은 v1 판정에서 계속 허용됩니다.
