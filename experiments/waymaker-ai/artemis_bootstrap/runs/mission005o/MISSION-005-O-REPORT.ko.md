## 2. 이번 미션에서 바꾼 것

시스템 동작과 응답 계약(v11)은 005-N과 같습니다. 바꾼 것은 판정 기준 둘과 새 수용 집합입니다.

1. **충돌 판정을 내용으로(소유자 결정 (다)).** 충돌이 기대되는 사례에서 한쪽 값을 빠뜨리거나, 충돌하는 문서를 다 인용하지 않거나, 한쪽을 고르면 치명입니다.
   두 값을 모두 적고 둘 다 인용했으면 상태 오류입니다. 명세 6절에 적고 `conflict_resolution.py`로 판정합니다.
2. **범주 기준 3건 중 2건(소유자 결정).** 범주마다 3건이라 0.75는 사실상 전부 맞히라는 뜻이었습니다. 원 모델 전체 0.85와 치명 0건은 그대로입니다.
3. **새 수용 집합 81건(V-3 가상 체류자격).** 명세만 읽은 에이전트가 쓰고, 다른 에이전트가 기대값을 먼저 혼자 도출한 뒤 비교했습니다.
   결정 값은 77건이 완전히 같았고 4건은 분할 사례의 상태 표기 방식만 달랐습니다. 필수 언급과 금지 패턴은 세 번 고쳤습니다.
   005-M·005-N에서 맞는 답에 걸렸던 관계절·수동태·코드가 낀 명사구는 세 언어로 시험했습니다.
   한 자리 숫자가 두 자리 숫자 안에서 맞아 버리는 문제는 여섯 사례의 값을 두 자리로 바꿔 피했습니다.

## 3. 결과를 읽어 보면

- **충돌 3건은 모두 모델이 `conflict`로 답했습니다.** 그래서 새 충돌 규칙은 이번 판정에 쓰이지 않았습니다.
  이번 충돌 질문 셋 중 둘은 "문서가 서로 다르다"고 먼저 말했습니다. 005-M·005-N처럼 "각각 얼마로 정했나"를 묻는 꼴은 없었습니다. 그 꼴에서 모델 습관이 바뀌었는지는 이번 결과로 알 수 없습니다.
- **부분 답 6건 중 5건이 빠진 항목을 스스로 말했습니다**(005-N 2/6, 005-M 3/6). `partial_response` 범주는 3/3입니다. 나머지 1건(A05O-48)은 시스템 안내가 채웠습니다.
- **수용 집합 패턴 오류는 0건입니다.** 맞는 답에 금지 패턴이 걸린 경우가 없었습니다.

## 4. 남은 실패

**모델: 베트남어 질문에 한국어로 답함(A05O-36·39·45)**
- 세 답 모두 근거의 한국어 문장을 거의 그대로 옮겼습니다. 내용은 맞았지만 답 언어 검사가 막아 사용자에게는 "검토가 필요하다"는 보류 문장이 나갔습니다.
- 그래서 끝단 오답 3건이 모두 이 경우입니다. 위험한 답은 나가지 않았습니다.
- 45는 "한국어나 영어로 답해도 된다"는 이중 요청을 지운 질문이라 답 언어는 베트남어가 맞습니다.
- 모델을 부른 베트남어 질문 24건 중 3건입니다. 영어 질문 18건에서는 0건입니다.

**모델: 부분 답에서 빠진 항목을 말하지 않음(A05O-48)**. 시스템 안내가 끝단을 맞췄습니다.

## 5. DEV-20

- 게이트를 통과해 같은 런타임에서 DEV-20을 한 번 처리했습니다. `run_dev20`이 봉인된 통과 기록을 다시 채점해 확인한 뒤 실행했습니다.
- 실제 신뢰 기록부(`registry/real_world_registry.json`)가 없으므로 20건 모두 `registry_unavailable`로 추론 전에 보류했고, 모델은 한 번도 부르지 않았습니다.
- 이것은 005-G부터 미리 정한 동작입니다. 평가 쪽 승인 상태를 기록부 대신 쓰지 않습니다. 그래서 이번 DEV-20은 "닫힌 쪽으로 실패한다"는 것만 확인하고 정확도는 재지 않습니다.

## 6. 다음 미션 제안

1. **실제 신뢰 기록부(소유자 결정).** 실제 문서에서 DEV-20을 재려면 실제 근거마다 출처·발행 기관·적용 범위·효력일을 사람이 확인한 기록이 있어야 합니다.
   실제 법령·매뉴얼 내용을 승인하는 일이라 모델이나 에이전트가 대신할 수 없습니다. 누가 어떤 근거로 승인할지 소유자가 정해야 합니다.
   기록부 형식과 검사는 이미 있으므로, 정해지면 DEV-20 근거 몇 건부터 시작할 수 있습니다.
2. **베트남어 답 언어.** 답 언어 검사가 막은 경우 시스템이 답 언어를 다시 알리며 모델을 한 번 더 부르는 방법이 있습니다. 결정적 규칙이라 시스템 쪽에서 할 수 있습니다.
   다만 모델 호출이 늘고 원 모델 채점의 뜻(첫 답 기준)을 바꾸므로, 원 모델 채점은 첫 답으로 두고 끝단만 다시 부른 답으로 세는 방식을 권합니다.
3. **충돌 질문의 꼴.** 다음 수용 집합에는 "각각 얼마로 정했나"처럼 문서별 값을 묻는 충돌 질문을 하나 이상 넣어, 새 충돌 규칙이 실제 답에서 어떻게 작동하는지 봅니다.
