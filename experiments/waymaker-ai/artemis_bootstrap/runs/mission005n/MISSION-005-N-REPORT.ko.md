## 5. 다음 미션 제안과 소유자 결정

남은 실패는 시스템 쪽 결정 규칙이 아니라 기준의 뜻과 모델 습관에 걸려 있습니다.

1. **충돌 상태 규칙(소유자 결정).** 지금 기준은 충돌이 기대되는 사례에서 상태가 `answered`이면 내용과 상관없이 "충돌을 한쪽으로 정리"로 셉니다.
   두 미션에서 이 규칙으로 센 치명 4건은 모두 두 값을 다 적고 둘 다 인용한 답이었습니다. 선택지는 셋입니다.
   - (가) 기준 유지: 모델이 상태를 바꿀 때까지 실패로 둡니다. 계약 문구는 두 번 효과가 없었으므로 다른 방법(예: 미세 조정)이 필요합니다.
   - (나) 시스템이 상태를 정함: 인용한 두 채택 근거가 같은 항목에 다른 값을 주고 답이 두 값을 모두 적으면 시스템이 상태를 `conflict`로 표시합니다. 끝단은 맞지만 원 모델 채점은 그대로 실패입니다.
   - (다) 치명 판정을 내용 기준으로: 한쪽 값만 적거나 한쪽을 맞다고 하면 치명, 두 값을 모두 적고 둘 다 인용하면 상태 오류(치명 아님)로 셉니다. 게이트의 판정 규칙을 바꾸는 일이라 소유자 결정입니다.
   권고는 (다)입니다. 사용자가 받는 글에는 아무것도 정리되지 않았습니다. 이 규칙이 막으려는 위험(한쪽을 고름)은 내용으로 판정할 수 있습니다.

   **결정(2026-11-02): 소유자가 (다)를 택했습니다.** 판정은 `conflict_resolution.py`에 있고, 다음 미션의 게이트 v10이 상태만 보는 규칙 대신 이 판정을 씁니다.
   - 치명: 한쪽 값을 빠뜨림, 충돌하는 문서를 다 인용하지 않음, 한쪽이 적용된다·우선한다·대체되었다고 말함.
   - 상태 오류(치명 아님): 두 값을 모두 적고 두 문서를 모두 인용했으며 어느 쪽도 고르지 않음. 원 모델 채점은 실패이고 끝단도 정답으로 세지 않습니다.
   - 값 그룹이 둘 미만인 충돌 사례는 양쪽을 확인할 수 없으므로 치명으로 셉니다.

   005-M과 005-N의 고정된 판정은 바꾸지 않습니다. 참고로 새 규칙으로 다시 세면 두 미션 모두 상태 치명 2건이 빠지지만, 수용 집합 패턴 오류 1건(A05M-62, A05N-61)이 남아 여전히 fail입니다.
2. **수용 집합 검토 지침.** 역할 패턴은 관계절("the institution that invited the R-4-2 lecturer must …", "…를 초청한 기관이 …")과 코드가 낀 명사구로도 시험합니다.
3. **부분 답 문장.** 005-M에서 정한 대로 모델 쪽 규칙으로 둡니다. 이번에도 계약 문구로는 절반을 넘지 못했고 시스템 안내가 끝단을 맞췄습니다.
   원 모델 `partial_response` 범주는 이 방식으로 넘기 어렵다는 점을 다시 기록합니다.
