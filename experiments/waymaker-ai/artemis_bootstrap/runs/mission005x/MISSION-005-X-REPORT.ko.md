## 2. 고르는 질문 여섯 건 (합성 시험)

질문이 두 코드 중 어느 쪽인지 물으면 코드마다 모델을 따로 불렀고, 두 답을 질문 순서대로 이었습니다. 여섯 건 모두 원 모델에서 통과했습니다.

| 문항 | 언어 | 처음 답 | 부분 답 |
|---|---|---|---|
| 02 | 베트남어 | 두 코드·두 값 | 두 부분 모두 두 코드를 비교 |
| 33 | 베트남어 | 두 코드·두 값 | 두 부분 모두 두 코드를 비교 |
| 45 | 한국어 | 두 코드·두 값 | 두 부분 모두 두 코드를 비교 |
| 70 | 한국어 | 두 코드·같은 값 | 두 부분 모두 "둘 다 35,000원" |
| 22 | 영어 | 두 코드·두 값 | 첫 부분은 비교, 둘째 부분은 맞는 코드만 |
| 62 | 영어 | 두 코드·두 값 | 첫 부분은 비교, 둘째 부분은 맞는 코드만 |

- **어떻게 나아졌나:** 모델은 "이 코드만 다루라"는 지시를 대부분 따르지 않았습니다. 12개 부분 가운데 10개가 두 코드를 함께 비교했습니다.
  나아진 이유는 코드별로 답을 따로 받은 데 있다기보다, 부를 때마다 모델이 비교 문장을 쓴 데 있습니다. 두 번 부르니 적어도 한 번은 두 코드를 다 쓴 것입니다.
- **대가:** 사용자에게 나가는 답에 같은 비교가 두 번 들어갑니다. 내용은 맞지만 중복입니다.
- **값 검사:** 한 번도 걸리지 않았습니다. 다른 코드의 값은 모두 그 코드 이름과 같은 문장에 있었고, 명세상 이런 문장은 대비로 봅니다. 바뀐 값은 없었습니다.
- **가까운 경우 4건(18·58·60·81):** 코드별로 나뉘지 않았고 모두 통과했습니다. 81은 하위 코드별 부분(005-J)으로 나뉘었습니다.

## 5. DEV-20 v2

- 통과하지 못한 것은 002·003·004·005·006·010입니다. 005-W와 비교하면 003과 006이 새로 떨어졌고 020이 통과로 바뀌었습니다.
- **003·004(고르는 질문):** 코드마다 두 번 불렀지만 두 부분이 글자까지 같은 답을 냈습니다. 맞는 코드(D-2-2, E-7-4)만 썼습니다.
  다른 코드(D-2-1, E-7-1)를 물은 부분도 그 코드를 쓰지 않았습니다. 탐욕적 디코딩이라 지시가 거의 같은 두 입력에서 같은 답이 나온 것으로 봅니다.
  005-X는 코드별 부분에서 빠진 코드 검사를 껐습니다. 이은 답이 모든 코드를 다룬다고 가정했기 때문입니다. 그래서 다시 묻기도 안내도 없었습니다.
  003은 005-W 때 안내 덕분에 통과했는데 이번에는 `전문학사`가 빠져 떨어졌습니다. 004는 `전문인력`이 빠졌습니다.
  **이 가정은 틀렸습니다.** 합성 시험에서는 맞았지만 실제 기록부 질문 두 건 모두에서 어긋났습니다.
- **006:** 같은 입력에 지시문만 바뀌었는데 답에서 `의무적으로 제출`이 빠졌습니다. 004 때와 같은 지시문 민감성입니다.
- **020:** `제출해야` 대신 `내야`라고 써서 통과했습니다. 역시 표현이 바뀐 결과입니다.
- **011:** 처음 답이 두 경우를 모두 써서, 005-W 때 일어난 두 경우 다시 묻기가 필요 없었습니다.
- 그 밖에 모델을 부른 문항 중 5건은 005-W와 글자까지 같고, 4건은 표현만 바뀌었습니다(005·008·018과 011). 상태가 바뀐 문항은 없습니다.
