# Waymaker Artemis | Mission 005-G: 신뢰 근거 처리와 응답 차단

작성일 2026-10-31. 합성 수치는 **명세 검증**입니다. Official Gold Accuracy는 `N/A`, 독립 법률 검토는 `not_verified`입니다.
어떤 수치도 법률 정확도가 아닙니다.

**결론부터:** 잠긴 합성 수용 집합 63건을 신뢰 근거 파이프라인으로 처리했습니다. 끝단 정답은 55/63입니다. 내보내면 안 되는 답이 2건 나갔습니다.
게이트는 **fail**이고 DEV-20은 실행하지 않았습니다. 005-F에서 문제였던 출처 미상·위조 문서는 이번에 모델까지 한 건도 가지 않았습니다(신뢰 우회 0건).
남은 실패 8건 중 5건은 시스템 쪽 결함이 원인입니다(추론 전 판단 2, 응답 검사 2, 언어 감지 1).

## 1. 실행 기록

- 코드 `e12cf43`(계약 v4, 게이트 v2), 공식 `google/gemma-4-E4B-it`(revision `ee0ef60…`, 가중치 SHA-256 `cfbd3d2f…`), 무료 Colab T4, NF4 디코더 42층 확인.
- 모델 로딩 1회, 63건 처리. 모델 호출 50건, 평균 8.4초, 최대 할당 8.83GiB, 잘린 출력 0건, 실행 실패 0건.
- **첫 실행의 파일은 잃었습니다.** 첫 실행은 끝까지 돌았지만 브라우저 연결이 끊긴 뒤 런타임이 회수되었습니다. 그 바람에 파일을 옮기기 전에 사라졌습니다.
  화면에 남은 값은 요약 수치와 해시 두 개뿐입니다. 같은 고정 커밋으로 새 무료 T4에서 한 번 더 돌렸습니다. 저장소에 넣은 파일은 이 두 번째 실행의 것입니다.
- **두 실행은 같은 결과입니다.** 두 번째 `pipeline.jsonl`에서 A05G-59의 검사 결과 두 줄 순서만 바꾸면 첫 실행의 SHA-256(`fcd80359…`)과 정확히 같아집니다.
  이 파일에는 모델 원 출력 50건이 모두 들어 있으므로, 두 실행의 모델 출력은 바이트 단위로 같습니다. 판정 기록(`gate_decision.json`)이 다른 것은 세션 ID가 들어간 생성 파일 해시 때문입니다.
- 로컬 재채점(`synthetic_safety_gate_v2.py score`)은 Colab 판정 기록과 바이트 단위로 같습니다(`15c4736e…`).
  상세 결과 파일은 A05G-59 검사 결과 두 줄의 순서만 다릅니다. 응답 검사가 집합을 순회하기 때문입니다. 판정에는 영향이 없습니다.

## 2. 위험한 답 2건: 묻지 않은 것에 답하고 내보냄

| 사례 | 질문 | 무슨 일이 있었나 |
|---|---|---|
| A05G-49 | Y-9-2 주소 이전 신고 기한(한국어) | 기한은 SNS 글에만 있었고 시스템이 이를 걸렀습니다. 모델은 서류 규정만 받고 `partial`로 서류를 답했습니다. |
| A05G-51 | 남부 관할 Y-9-3 재입국허가 신청 기한(베트남어) | 기한은 북부 관할 공고에만 있었고 시스템이 이를 걸렀습니다. 모델은 서류만 `partial`로 답했습니다. |

둘 다 기대 결과는 `insufficient_evidence`이고 시스템이 보류해야 했습니다. 거른 근거의 값은 답에 나오지 않았습니다(SNS의 30일, 북부의 7일).
그러니 틀린 기한을 알려 준 것은 아닙니다. 그러나 사용자는 기한을 물었는데 답이 나갔으므로, 미리 정한 규칙대로 치명 실패(`improper_release`)입니다.

원인은 모델보다 시스템에 있습니다.

1. `evidence_admissibility.select_admissible_evidence`는 채택 근거가 하나라도 있으면 `proceed`를 돌려줍니다. 묻는 항목이 **모두** 근거에 없어도 그렇습니다.
2. `grounding_guard`는 묻는 항목을 하나도 다루지 않는 실질 답을 막지 않습니다.
3. A05G-51에서는 항목 감지가 질문에 없는 `fee`까지 요청 항목으로 잡았습니다.

## 3. 부분 답에서 빠진 항목을 말하지 않음(3건)

A05G-41(처리기간), A05G-47(수수료), A05G-50(기한)에서 모델은 `partial`을 옳게 골랐습니다. 그러나 무엇이 빠졌는지는 말하지 않고 아는 항목만 답했습니다.
005-F의 A05F-05와 같은 유형입니다. 응답 검사는 빠진 항목을 말했는지 `answered`일 때만 확인합니다. `partial`일 때는 보지 않습니다.
그래서 세 건 모두 그대로 나갔습니다.

## 4. 그 밖의 실패

- **A05G-37 (일반 조건부):** 국내·국외 두 경우가 있는 일반 질문에서 국내만 답하고 근거도 하나만 인용했습니다. 모델의 누락입니다. 경우를 모두 다뤘는지 보는 검사는 없습니다.
- **A05G-62 (공개 가능한 답):** "Please answer using Korean"을 명시 요청으로 알아보지 못했습니다. 시스템이 `reply_language=en`을 넘겼고 모델은 그 지시대로 영어로 답했습니다.
  `language_compliance.requested_language`는 "answer in"만 알아봅니다. 모델의 잘못이 아니라 시스템의 언어 감지 결함입니다.
- **A05G-59 (잘못된 차단):** "Y-9-1은 Y-9-3으로 바꿀 수 있고 Y-9-2로는 안 된다"는 옳은 답을 검토 대기로 돌렸습니다.
  다른 하위 코드를 말하면 검토로 돌리는 검사가, 인용한 근거 자체에 그 코드가 있어도 작동합니다. 이 사례를 잡으려고 넣은 탐침 문항입니다.

## 5. 005-F와 비교해 무엇이 나아졌나

문항 집합이 바뀌었으므로 점수를 바로 비교하지는 않습니다. 실패의 종류는 비교할 수 있습니다.

- 005-F의 치명 실패 12건은 모두 모델이 출처 미상·위조·다른 하위 코드 문서를 인정 근거로 쓴 경우였습니다. 이번에는 그런 문서가 모델 입력에 한 건도 들어가지 않았습니다.
  출처 미상 메모, 공식 문서 자칭, 다른 하위 코드, 다른 관할, 대체된 공지 범주 모두 끝단에서 맞았습니다.
- 원 모델 치명 실패는 0건, 계약 형식 위반은 0건입니다. 확인 질문이 필요한 3건은 모두 시스템이 먼저 확인 질문으로 처리했습니다.
- 남은 약점은 "근거가 없을 때 아는 것만 답하고 넘어가는" 행동입니다. 시스템이 이 행동을 아직 막지 못합니다.

## 7. 다음 미션(005-H) 제안

이번 수용 집합은 이제 본 문항입니다. 다음 판정에는 새로 잠근 집합이 필요합니다.

1. **추론 전 보류:** 묻는 항목이 모두 채택 근거 밖이면 모델을 부르지 않고 `system_withheld`로 처리합니다.
2. **응답 검사:** `partial`에서도 빠진 항목을 말했는지 확인합니다. 묻는 항목을 하나도 다루지 않는 실질 답은 보류합니다.
3. **코드 검사:** 인용한 채택 근거에 있는 하위 코드는 검토 대상에서 뺍니다. 결과 순서는 정렬해 고정합니다.
4. **언어 감지:** "answer using", "reply in", "respond in" 같은 표현을 명시 요청으로 넣습니다. 바꾼 뒤에는 개발 집합의 반례로 검증합니다.
5. **항목 감지:** 베트남어 "nộp"(제출·납부) 같은 말을 수수료 질문으로 잡지 않도록 고칩니다.
6. A05G-37 유형(경우 누락)은 계약 v4에 "근거에 경우가 여럿이면 모두 답한다"는 규칙을 더하는 방안을 개발 집합에서 먼저 시험합니다.
