# Mission 005-F 권고

근거: [Mission 005-E 보고서](MISSION-005-E-REPORT.ko.md), `score_comparison.json`, `synthetic_validation/synthetic_validation_results.json`.
모든 수치는 개발 진단이고 Official Gold Accuracy는 `N/A`, 독립 법률 검토는 `not_verified`입니다.

## 먼저 할 일

1. **합성 검증을 실행 문턱으로 바꿉니다.** 005-E는 합성 15건(11/15)을 DEV-20 직전에 돌렸지만 결과로 실행을 멈추지 않았습니다.
   005-F는 합성 결과가 미리 정한 기준(상태별 최소 통과 수)을 넘을 때만 DEV-20을 돌리고, 기준은 실행 전에 커밋으로 고정합니다.
2. **합성 집합을 넓힙니다.** 지금은 규칙당 1~2건이라 한 건의 실패가 곧 규칙 실패입니다. 특히 아래를 규칙당 여러 건으로 늘립니다.
   - 진짜 부분 답(여러 항목 중 일부만 근거가 있음)
   - 조건부 확인 질문(국내·국외, 현재 체류자격)
   - 한국어 근거와 외국어 질문
   - 커뮤니티 글과 공식 근거가 다른데 충돌이 아닌 경우
   새 사례는 DEV-20을 바꿔 쓰지 않고 새로 씁니다.
3. **DEV-20 채점에 응답 언어 검사를 넣습니다.** 지금은 언어 위반(DEV-011)이 점수에도 검토 표시에도 드러나지 않습니다. 점수를
   바꾸는 차원으로 넣을지, 따로 집계할지는 먼저 정하고 기대 정답은 고치지 않습니다.

## 계약 v3 후보 (DEV-20을 보지 않고 합성으로만 검증)

- `partial`: "답한 부분과 근거가 없는 부분을 나눠 말하라"를 앞으로 당기고, "질문이 여러 항목을 물으면 항목마다 근거가 있는지 확인하라"를
  넣습니다. 지금 문구가 진짜 부분 답까지 `answered`로 몰았을 수 있습니다(S05E-03).
- `conflict`: "커뮤니티 글·출처 미상과 공식 근거의 차이는 conflict가 아니며 커뮤니티 글은 인용하지 않는다"를 상태 정의 안에 다시 씁니다(DEV-020).
  `conflict`에 인용 2개를 요구하는 파서 규칙은 "둘 다 공식 근거"까지 요구하도록 강화할지 검토합니다.
- `clarify`: 조건에 따라 답이 갈릴 때 조건별로 모두 답하는 것을 허용할지 정책을 먼저 정합니다. 허용하지 않으면 지금 문구를 지키고
  합성 사례를 늘립니다. 반대로 질문에 이미 적힌 사실은 되묻지 말라는 문장을 넣습니다(DEV-002).
- 언어: "근거가 한국어여도 답은 질문의 언어로 쓴다"를 명시합니다(DEV-011, S05E-13·14).

계약을 바꾸면 v3로 올리고, v1·v2 기록과 프롬프트 SHA-256은 그대로 둡니다.

## 평가기

- E3 정규화는 부사만 다룹니다. "할 수 없다"↔"금지된다" 같은 바꿔 말하기는 결정적 규칙으로 안전하게 다룰 수 있을 때만 넣고,
  그렇지 않으면 `unresolved`로 남깁니다. LLM 판정기를 들이지 않습니다.
- 인용 근거가 답의 각 문장을 뒷받침하는지 보는 결정적 검사(숫자·날짜·코드가 인용 근거에 있는지)를 검토합니다.
- 필수 사실 중 "대비 설명"(DEV-003·004)과 "핵심 결론"을 나눠 기록할지 검토자에게 묻습니다. 기대 정답 자체는 바꾸지 않습니다.
