## 1순위: 출처 권위 (치명 실패 12건 전부)

모델은 출처 종류가 없는 메모와 공식을 자칭한 위조 문서를 인정 근거처럼 썼고, 다른 하위 코드의 규정을 질문 대상에 적용했습니다.
프롬프트 문구만으로는 막지 못했습니다. 다음을 차례로 시험합니다.

1. **입력 단계에서 거르기.** 검증된 처리 단계가 비인정으로 표시한 근거는 모델에게 아예 보내지 않거나, 별도 "참고용·비인정" 묶음으로 나눠 보냅니다.
   거르는 기준은 신뢰 기록에서만 가져오고 문서 본문에서는 가져오지 않습니다.
2. **결정적 후처리.** 답이 비인정 근거를 인용하거나 비인정 근거에만 있는 값을 쓰면 답을 보류합니다. 이 검사는 이미 `claim_support_validation.py`와
   게이트 채점에 있으므로 운영 경로의 보류 규칙으로 옮길 수 있는지 설계합니다(운영 반영은 별도 PR과 소유자 승인).
3. 하위 코드·대상 범주 불일치(질문은 Y-8-1, 근거는 Y-8-2)는 근거 선택 단계에서 코드 일치를 확인합니다.

## 2순위: 확인 질문 정책

개인 판단 질문 4건 모두 확인 질문 대신 조건별 답을 했습니다. 먼저 정책을 정합니다.
조건별 답이 모든 경우를 정확히 덮고 각 조건을 분명히 밝히면 허용할지, 개인 판단이면 반드시 물을지를 정합니다.
반드시 묻기로 하면 "제가/I/tôi + 할 수 있나요/해야 하나요" 같은 개인 판단 신호를 프롬프트에서 예시로 보여 주는 방안을 개발 집합에서 시험합니다.

## 3순위: 답 언어

- 한국어·베트남어 질문 7건이 영어 답이었습니다. 답 언어 지시를 프롬프트 맨 끝으로 옮기는 방안을 비교합니다.
  사용자 메시지에 "답 언어: ko" 같은 결정적 표시를 넣는 방안도 함께 비교합니다. 이 표시는 질문에서 결정적으로 계산한 값입니다.
- 프롬프트 문장을 답에 그대로 옮기는 현상(4건)을 막기 위해 상태 정의 문장을 답에 쓰지 말라는 지시가 필요한지 시험합니다.
- 언어 검사는 지금처럼 별도 지표로 둡니다.

## 4순위: 부분 답

부분 답 정답 4건 중 2건만 맞았습니다. "질문의 항목마다 근거 유무를 확인하라"는 지시만으로는 부족했습니다.
항목 목록을 내부적으로 만들되 출력하지 않게 하는 방식은 작은 모델에서 불안정할 수 있습니다. 그래서 개발 집합에서 먼저 시험합니다.

## 평가기

- 영어·베트남어 날짜 읽기를 추가할지 정합니다(결정적 규칙과 반례 테스트로만).
- 비한국어 답의 역할 반전은 지금 사례 명세의 금지 문장에 의존합니다. 범용 규칙을 넣으려면 반례를 먼저 모읍니다.
- 수용 집합의 기준 답을 사례 작성자와 다른 작성자가 쓰게 해 평가기 검증의 독립성을 높입니다.
