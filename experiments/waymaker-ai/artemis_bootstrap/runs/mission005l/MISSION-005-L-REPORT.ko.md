## 3. 남은 실패

- **문서 제목의 연도를 기간으로 읽음(A05L-28·29, 답 검사).** 두 근거의 처리기간(15일·25일)과 수수료(20,000원·26,000원)가 달라 모델은 둘 다 들어 `conflict`로 맞게 답했습니다.
  답에 출처로 "가상 하람이주청 U-3 운영지침(2026년판)"을 적었는데, 근거 대조 검사가 "2026년"을 기간 주장으로 봤습니다.
  A05L-28은 원 모델 채점에서 근거와 어긋남으로, 응답 검사에서 보류로 처리됐습니다. A05L-29는 원 모델은 통과했지만 응답 검사가 근거 없는 기간으로 보아 보류했습니다(잘못된 차단 1건).
- **부분 답의 빠진 항목(A05L-42·48, 모델).** 묻는 것 가운데 근거에 없는 항목(처리기간, 수수료)을 답에서 말하지 않았습니다. 시스템 안내가 채워 끝단은 맞았습니다. A05K-41·47과 같은 습관입니다.

## 4. 수용 집합이 드러낸 명세 빈틈

작성 에이전트는 미검증·검토 대기 기록에 검증 방법 `registry_lookup`을 적었습니다. 그런데 코드는 합성 기록부 안에서 방법이 `synthetic_fixture`가 아닌 기록을 없는 기록으로 봅니다.
그래서 9건이 기대한 사유(`unverified_source` 등) 대신 `no_registry_record`로 거절됐습니다. A05L-12는 검토 필요 대신 시스템 보류가 됐습니다. 명세에는 이 규칙이 없습니다.
모두 닫힌 쪽으로 거절됐고 9건 모두 끝단 정답이라 안전에는 영향이 없습니다. 추론 전 사유 일치가 72/81로 내려갔지만, 이 값은 판정 문턱이 아닙니다.

## 5. 다음 미션(005-M) 제안

기준은 그대로 둡니다.

1. **근거 대조에서 채택 근거의 제목을 근거로 봄.** 답에 나온 값이 채택 근거의 제목에 그대로 있으면(문서 이름의 연도·판 등) 근거 없는 값으로 보지 않습니다.
   005-K에서 근거 속 한국어 이름을 답 언어 검사에서 뺀 것과 같은 방식이고, 결정적입니다. 원 모델 채점과 응답 검사에 함께 적용합니다.
2. **명세에 기록부 검증 방법 규칙을 적음.** 합성 기록부에서는 `synthetic_fixture` 기록만, 실제 기록부에서는 그 밖의 기록만 인정한다는 현재 동작을 1절에 씁니다.
3. 언어 요청 빼기에서 쉼표 뒤 `please`와 남는 조사 `로`를 처리합니다. 이번에는 모델이 맞게 답했으므로 개발 집합에서 먼저 봅니다.
4. 부분 답의 빠진 항목은 시스템 안내가 끝단을 맞추고 있습니다. 원 모델 범주 문턱에 다시 걸리면 계약 문구보다 결정적 방법(예: 부분 답일 때 모델에게 빠진 항목 이름을 문장째 주기)을 개발 집합에서 먼저 시험합니다.
