## 2. 추출을 신뢰할 수 있는 근거

두 매뉴얼 모두 **배포용 HWP**(FileHeader flag `0x4`)입니다. `BodyText`는
스텁(334B / 325B)이고 본문은 `ViewText`에 AES-128-ECB로 암호화되어 있어,
`scripts/decrypt_hwp_distribution.py`로 읽었습니다.

이 스크립트를 **이미 사람이 승인한 2026-07-31 판**에 다시 돌린 결과, 저장소에
커밋된 검증본과 **바이트 단위로 완전히 일치**했습니다.

```
docs/source-manuals/2026-07-31/extracted/full_text/visa_manual_260731.txt
  커밋본  a80ec1f34da8ebf3b87e6cb306f69d3fd8e96a3919204de2989dbccb8419e080
  재추출  a80ec1f34da8ebf3b87e6cb306f69d3fd8e96a3919204de2989dbccb8419e080  ✅
stay_manual_260731.txt 도 동일하게 일치 ✅
```

즉 "추출 방식이 맞는가"는 검증된 사실입니다. 남은 것은 "내용이 맞는가"이며,
그것은 사람의 대조 작업입니다.

## 4. 근거 게이트가 닫혀 있는 이유

`backend/services/manual_registry.py`의 설계상 **`approved` 상태의 판본만**
AI 답변의 직접 근거가 될 수 있습니다. 현재:

- 260731 판 → `superseded` (260901이 대체)
- 260901 판 → `needs_review` (사람 검토 전)

따라서 사증/체류 매뉴얼 계열에 `approved` 판본이 없어 **직접 근거 게이트가
닫혀 있습니다.** 이는 의도된 fail-closed 동작이며 결함이 아닙니다.
`needs_review` 상태 콘텐츠는 여전히 **검색은 되고 `검토 전`으로 라벨링**됩니다.

## 5. 승인 절차

`data/manual_approval_index.json`의 `visa_manual_2026_09_01_hwp` /
`stay_manual_2026_09_01_hwp` 항목에서:

```json
"approval_state": "needs_review",   →   "approved"
"reviewer": "",                     →   "<검토자 식별자>"
"reviewed_at": "",                  →   "<YYYY-MM-DD>"
```

자동화 파이프라인은 이 값을 설정할 수 없습니다
(`data/manual_approval_index.json` 주석: *"Nothing in the automated pipeline
may set 'approved'."*). 반드시 사람이 원문과 대조한 뒤 기록해야 합니다.

## 6. 이번 작업에서 하지 않은 것

CLAUDE.md의 보호 파일 규칙에 따라 **다음은 전혀 건드리지 않았습니다.**

- `visa_data.json`
- `backend/data/visas.json`
- `doc_master.json`
- `backend/data/doc_master.json`

새 매뉴얼 내용을 이 파일들에 반영하는 작업은 **별도 작업**이며, 3절의 코드별
검토가 끝난 뒤에 진행해야 합니다. 매뉴얼이 갱신되었다는 사실만으로 법령 요건을
자동 재작성하지 않았습니다.
