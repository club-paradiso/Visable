# 쉬운 안내(Easy Mode) 정확성·접근성 감사 및 수정 — 2026-07-03

사용자 제보: "쉬운 모드가 잘못된 정보를 제공하거나 오류가 많다."
라이브(main)와 동일한 커밋을 실제 브라우저(Chromium/Playwright)로 구동해 재현·확정한
결함과 렌더러 수준 수정 내역. 데이터 파일(visa_data.json 등)은 일절 수정하지 않음.

## 확정된 결함 (수정 전 재현 결과)

1. **요약 필드 불일치 — 모든 카드가 "준비되지 않음" 폴백 표시.**
   `renderEasyModePanel`이 `v.summary`만 읽었으나 `summary` 필드는 42개 레코드 중
   0개에 존재. 결과적으로 모든 쉬운 안내가 "아직 자세히 준비되지 않아…" 공지와
   내용 없는 일반 문구만 표시했다. 압축 결과 카드·복사 기능은 이미
   `summary → newReq → extReq` 체인을 사용 중이었음.

2. **절차 혼합 서류 목록 (핵심 오정보).** `getEasyModeDocNames`가
   최초 신청(입국 전)·외국인등록·체류기간 연장 서류를 단계 표기 없이 하나의
   "보통 필요한 서류" 목록으로 평탄화하고 8개에서 잘랐다.
   - D-2 기준: 입국 전 사증 단계 서류 5개 + 외국인등록 서류 3개가 한 목록으로
     섞이고, 체류기간 연장 서류는 전부 누락됨.
   - 절차 범위 분리 원칙(사증발급 ↔ 체류 절차 혼합 금지)의 렌더링 위반.

3. **서류가 아닌 행이 "서류"로 표시.** 표준 탭 데이터의 주의 표식
   ("체류민원 기준 주의"), 수수료 행("수수료…", "외국인등록증 발급 수수료"),
   각주 별표가 붙은 이름("체류지 입증서류*")이 체크마크와 함께
   준비할 서류처럼 렌더링됨.

4. **접근성 결함.**
   - 뷰 전환기가 `role="tablist"/"tab"` + `aria-selected`를 사용했으나
     tabpanel 연결(aria-controls), roving tabindex, 방향키 지원이 전무 —
     스크린리더에 탭이라고 알리면서 탭처럼 동작하지 않음.
   - `.easy-mode-panel`의 aria-label이 role 없는 div에 있어 보조기기가 무시.
   - 패널 내 "공식 근거 보기" 버튼은 클릭 시 자신이 숨겨져 포커스가 body로 유실.
   - 뷰 전환 버튼 터치 타깃이 약 30px로 작음.

## 적용한 수정 (전부 렌더러/리졸버 계층)

- 요약을 압축 카드와 동일한 `summary → newReq → extReq` 체인으로 해석.
  한국어 UI에서만 원문 2문장(240자 초과 시 1문장) 표시, 비한국어 패널에는
  기존 정책대로 한국어 원문 누출 없음. 폴백 공지는 정규화 후에도 원문이
  진짜 없는 레코드에서만 표시.
- `getEasyModeDocGroups`: 표준 뷰가 쓰는 단계 라벨(현지화된
  `documentTabLabels`/절차 라벨) 아래 단계별 그룹으로 서류를 표시. 단계 병합
  금지, 단계당 5개 + "이 외 {count}개" 안내(신규 i18n 키 `easyModeDocsMore`,
  12개 로케일 전부 추가). 수수료/주의 행 및 꼬리 별표는 쉬운 안내에서만
  렌더링 제외(표준 뷰는 그대로 유지).
- 뷰 전환기를 `role="group"` + `aria-pressed` 토글 버튼으로 교체,
  `applyCardMode`도 동일하게 갱신. 패널에 `role="region"` 부여.
  패널 내 공식 근거 전환 시 포커스를 해당 전환 버튼으로 이동.
- 터치 타깃 확대(min-height, 모바일에서 공식 근거 버튼 전폭),
  섹션 제목 액센트 바, 서류 그룹 간격 등 시각 계층 정리.
- 회귀 가드: `tests/e2e/easy-mode.spec.mjs` (내용 계약 + 접근성 + 전역 토글).

## 남은 사항 / 수동 검토 필요

- **F-6**: `newReq` 전체가 렌더 계층에서 의도적으로 억제되는
  "[한국인]…[외국인]…" 터스 태그 요약이라, 정규화 후 요약이 비어 폴백 공지가
  유지됨(데이터에 정직한 동작). F-6에 서술형 개요 원문을 정비할지는
  데이터 작업으로 별도 판단 필요.
- `easyModeDocsUsuallyTitle`/`easyModeDocsMaybeTitle` 키는 더 이상 사용되지
  않지만 로케일 패리티 보호를 위해 팩에는 유지(제거는 별도 정리 작업).
- 쉬운 안내의 "이제 무엇을 하나요?" 일반 단계는 국내 체류 절차 관점의
  문구로, 단계별 서류 그룹 표기 도입으로 혼동 소지가 줄었으나 절차별
  맞춤 단계 문구(로케일 12종 번역 필요)는 후속 과제로 남김.
