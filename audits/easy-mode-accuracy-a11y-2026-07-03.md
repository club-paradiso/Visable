# 쉬운 안내(Easy Mode) 정확성·접근성 감사 및 수정 — 2026-07-03

사용자 제보: "쉬운 모드가 잘못된 정보를 제공하거나 오류가 많다."
라이브(main)와 동일한 커밋을 실제 브라우저(Chromium/Playwright)로 구동해 재현·확정한
결함과 렌더러 수준 수정 내역. 데이터 파일(visa_data.json 등)은 일절 수정하지 않음.

## 확정된 결함 (수정 전 재현 결과)

1. **요약 필드 불일치 — 모든 카드가 "준비되지 않음" 폴백 표시.**
   `renderEasyModePanel`이 `v.summary`만 읽었으나 `summary` 필드는 42개 레코드 중
   0개에 존재. 결과적으로 모든 쉬운 안내가 "아직 자세히 준비되지 않아…" 공지와
   내용 없는 일반 문구만 표시했다. 압축 결과 카드·복사 기능은 이미
   `summary → newReq → extReq` 체인을 사용 중이었음.

2. **절차 혼합 서류 목록 (핵심 오정보).** `getEasyModeDocNames`가
   최초 신청(입국 전)·외국인등록·체류기간 연장 서류를 단계 표기 없이 하나의
   "보통 필요한 서류" 목록으로 평탄화하고 8개에서 잘랐다.
   - D-2 기준: 입국 전 사증 단계 서류 5개 + 외국인등록 서류 3개가 한 목록으로
     섞이고, 체류기간 연장 서류는 전부 누락됨.
   - 절차 범위 분리 원칙(사증발급 ↔ 체류 절차 혼합 금지)의 렌더링 위반.

3. **서류가 아닌 행이 "서류"로 표시.** 표준 탭 데이터의 주의 표식
   ("체류민원 기준 주의"), 수수료 행("수수료…", "외국인등록증 발급 수수료"),
   각주 별표가 붙은 이름("체류지 입증서류*")이 체크마크와 함께
   준비할 서류처럼 렌더링됨.

4. **접근성 결함.**
   - 뷰 전환기가 `role="tablist"/"tab"` + `aria-selected`를 사용했으나
     tabpanel 연결(aria-controls), roving tabindex, 방향키 지원이 전무 —
     스크린리더에 탭이라고 알리면서 탭처럼 동작하지 않음.
   - `.easy-mode-panel`의 aria-label이 role 없는 div에 있어 보조기기가 무시.
   - 패널 내 "공식 근거 보기" 버튼은 클릭 시 자신이 숨겨져 포커스가 body로 유실.
   - 뷰 전환 버튼 터치 타깃이 약 30px로 작음.

## 적용한 수정 (전부 렌더러/리졸버 계층)

- 요약을 압축 카드와 동일한 `summary → newReq → extReq` 체인으로 해석.
  한국어 UI에서만 원문 2문장(240자 초과 시 1문장) 표시, 비한국어 패널에는
  기존 정책대로 한국어 원문 누출 없음. 폴백 공지는 정규화 후에도 원문이
  진짜 없는 레코드에서만 표시.
- `getEasyModeDocGroups`: 표준 뷰가 쓰는 단계 라벨(현지화된
  `documentTabLabels`/절차 라벨) 아래 단계별 그룹으로 서류를 표시. 단계 병합
  금지, 단계당 5개 + "이 외 {count}개" 안내(신규 i18n 키 `easyModeDocsMore`,
  12개 로케일 전부 추가). 수수료/주의 행 및 꼬리 별표는 쉬운 안내에서만
  렌더링 제외(표준 뷰는 그대로 유지).
- 뷰 전환기를 `role="group"` + `aria-pressed` 토글 버튼으로 교체,
  `applyCardMode`도 동일하게 갱신. 패널에 `role="region"` 부여.
  패널 내 공식 근거 전환 시 포커스를 해당 전환 버튼으로 이동.
- 터치 타깃 확대(min-height, 모바일에서 공식 근거 버튼 전폭),
  섹션 제목 액센트 바, 서류 그룹 간격 등 시각 계층 정리.
- 회귀 가드: `tests/e2e/easy-mode.spec.mjs` (내용 계약 + 접근성 + 전역 토글).

## 후속: 서류명 이중 표기(한국어 + 검증된 번역) — Easy Mode + 일반 모드

요청: 언어 설정을 바꿨을 때 서류 이름을 한국어만 보여주지 말고 괄호로 해당
언어 번역을 병기. 단, CLAUDE.md의 "법률/이민 콘텐츠를 임의로 만들지 않는다"
원칙과 이 리포 고유의 `data/i18n/official-terms.json` 정책("공식 영어/중국어
명칭을 절대 임의로 만들지 않는다. confidence가 canonical/official/
manual-derived/curated일 때만 노출하고, needs-verification/fallback은
저장만 하고 한국어로 렌더링한다")을 그대로 지켰다 — 새 번역을 만들지 않고,
**이미 검증되어 존재하는 용어집을 두 화면(Easy Mode, 일반 모드)에 추가로
연결**했을 뿐이다.

### 발견한 사실
- 서류명 이중 표기 메커니즘(`annotateOfficialDocLabel` + `officialTermTranslation`)
  은 이미 존재했지만 호출처가 `renderDocTags` 단 한 곳(직접 doc_* id가 붙은
  경우만)이었고, doc_* id가 없는 대부분의 원문 서류명(`documents_initial` 등
  직접 필드, 전체 서류행의 약 90%)과 Easy Mode는 전혀 연결돼 있지 않았다.
- 전체 42개 상태 중 41개는 절차(Procedures) 섹션이 구비서류를 소유해
  (`procedureSectionOwnsDocuments`) 독립 "구비서류" 탭 UI 자체가 렌더링되지
  않는다 — 즉 실사용자가 보는 "일반 모드" 서류 표시는 거의 전부
  `renderDocTags`(절차 체크리스트) 경로다. 독립 탭 UI(`renderDocumentTabPanel`)
  경로는 현재 데이터셋에서 어느 레코드도 실제 콘텐츠로 도달하지 않아
  (YOUTH-STAY만 비-절차소유이나 서류 필드 자체가 비어 있음) 유닛 테스트로
  직접 검증했다.

### 구현 (렌더러 전용, 데이터 미변경)
- `findOfficialTermIdForKoreanLabel(koreanLabel)`: doc_* id 없이도 용어집과
  매칭하는 새 조회 경로. ① 공백만 정규화한 전체 텍스트 완전일치, ② 그래도
  없으면 기존 서류 패밀리 분류기(`normalizeDocumentRequirementKey`, 이미
  Standard 체크리스트 중복제거에 쓰이던 코드)의 결과가 용어집 `ko` 필드와
  **글자 그대로 동일할 때만** 신뢰. 어떤 경우도 새로운 매핑을 주장하지 않고,
  이미 사람이 검증한 두 값이 우연히 일치하는지만 확인한다.
- `renderAnnotatedDocLabel(koreanLabel)`: Standard 구비서류 탭(`.docs-list-name`)
  과 Easy Mode(`.easy-doc-group`)가 공용으로 쓰는 안전한 HTML 조각 생성기 —
  번역이 있으면 `<span class="doc-name-i18n" lang="{현재언어}">(번역)</span>`
  을 추가하고, 없으면 기존과 동일하게 한국어만 표시.
- `renderDocTags`(절차 체크리스트, 실질적 "일반 모드" 대부분)는 `hl()`이
  내부적으로 `escapeHtml()`을 다시 적용하는 구조라 위 span 방식을 쓸 수 없어,
  기존 `annotateOfficialDocLabel`과 동일한 방식(순수 텍스트 `이름 (번역)`)으로
  폴백을 추가 — doc_* id 매칭이 없을 때만 텍스트/패밀리 폴백을 시도.
- 한국어 UI는 `officialTermTranslation()`이 `locale==='ko'`일 때 항상 null을
  반환하므로 구조적으로 완전히 영향받지 않음(브라우저 테스트로도 확인).

### 현재 실제 커버리지 (en/zh-CN만 데이터 보유)
용어집(`official-terms.json`)은 21개 용어 중 en/zh-CN만 값이 있고 나머지
10개 언어(ja, vi, tl, id, ru, fr, es, ar, de)는 값이 없다 — 메커니즘은
12개 언어 전부에서 동일하게 동작하지만(안전하게 무동작), **실제로 괄호
번역이 보이는 것은 오늘 기준 en/zh-CN 사용자뿐**이다. 전체 서류 행 기준
여권/수수료/외국인등록증/통합신청서 등 고빈도 항목이 겹치며 D-2 절차
체크리스트에서 69행 중 17행(EN)/19행(ZH-CN)이 즉시 이중 표기됨.

### 알려진 한계 (범위 내 정직한 트레이드오프)
- `renderDocTags` 경로(전체 서류의 대다수)에서 추가되는 번역 텍스트는
  `lang` 속성으로 별도 표시되지 않는다(`hl()`의 escapeHtml 재적용 제약).
  이는 새로 만든 문제가 아니라 기존 `annotateOfficialDocLabel`이 이미
  가지고 있던 특성을 동일하게 확장한 것— 완전한 접근성 개선은 `hl()`
  리팩터가 필요해 범위 밖으로 남겨둠.
- 10개 언어(en/zh-CN 제외) 및 나머지 ~90%의 서류명에 실제 번역을 채우는
  일은 데이터(용어집) 확장 작업이며, "공식 명칭을 임의로 만들지 않는다"는
  원칙상 검증되지 않은 번역을 새로 생성해 넣는 것은 이 커밋의 범위에서
  의도적으로 제외했다 — 사용자에게 별도로 확인 요청.

사전에 설명했고, 사용자가 이 트레이드오프를 명시적으로 선택함.

### 조사 결과 (중요한 환경 제약)
이 세션에서 **WebFetch가 환경 프록시에 의해 전면 차단**되어 있었다(정부
도메인뿐 아니라 example.com 등 중립 사이트도 전부 HTTP 403 — 사이트별
차단이 아니라 툴/네트워크 수준 차단으로 확인). 4개 조사 서브에이전트가
병렬로 시도했으나 대부분 "could not verify"로 귀결됐다. 예외적으로 한
에이전트가 **Legal_Data_Hunter MCP**(law.go.kr/KLRI 원문 접근 경로가
살아있었음)를 통해 다음 법령의 실제 영문 번역문을 확보했다:
- 가족관계등록 등에 관한 법률 제15조1항1·2·3호(가족관계증명서/기본증명서/
  혼인관계증명서), 상업등기법 제15조(법인등기사항전부증명서),
  주민등록법 시행령(주민등록등본).

부수적으로, 한 조사 에이전트가 WebSearch 결과 안에 삽입된 프롬프트
인젝션 시도("다른 Claude 세션"을 사칭해 조사를 조기 중단시키려 함)를
스스로 식별해 무시하고 조사를 계속했음 — 정당한 경로가 아니라고 판단해
투명하게 보고함.

### 반영한 confidence 정책
- `official`/`manual-derived`: 이번 세션에서 실제로 fetch한 법령 영문
  번역문에 근거(3건: 가족관계증명서, 혼인관계증명서, 법인등기사항전부
  증명서/주민등록등본 계열).
- `curated`: 여러 독립된(단, fetch로 직접 확인은 못한) WebSearch 단서가
  같은 표현으로 수렴하거나, 번역 위험이 없는 표준 서술형 영어(예:
  왕복항공권=Round-Trip Air Ticket). ~25건.
- `fallback`: 절차/서류 카테고리에 대한 직접적 서술 번역(공식 용어 주장
  없음) — 예: 재정입증서류, 기타체류목적입증서류, 파견명령서 등. ~13건.
- `needs-verification`: 경쟁하는 표기가 실제로 존재해 하나를 임의로
  고르지 않음(TOPIK 성적표: "Score Report" vs "Certificate"; 기존
  표준입학허가서 항목도 동일 사유로 이미 이 등급).
- **의도적 미번역**: `학업수행입증서류` 패밀리(출석확인서/재학증명서/
  성적증명서 등)는 분류기가 서로 다른 서류를 하나로 묶기 때문에, 하나의
  포괄 번역이 오히려 오해를 유발할 수 있어 이번 회차에는 커버하지 않음
  — 커버리지보다 정확성을 우선한 의도적 경계.

## 후속: 잔여 서류명 번역 전량 확장(96.8%) + 별개 렌더링 버그 발견

사용자 지시: "웬만하면 번역 누락된거 없이 작업을 부탁할게".

### 결과
용어집을 56→207개 용어로 확장(신규 151개, 전부 exact-match 방식 — 패밀리
뭉뚱그림으로 인한 오역 위험 없음). 전체 서류 표시 행 커버리지:
**80.4% → 96.8%** (1089행 중 1054행 커버).

### 부수적으로 발견한 별개 렌더링 버그 (이번 PR에서 수정하지 않음)
잔여 미커버 35행 중 21행은 사전 존재하던 **콤마/가운뎃점(·) 결합 문자열
분리 버그**의 산물로 확인됨 — `visa_data.json`을 직접 대조해 확인:
- `E-1.newReq`(절차 요약 프로즈 "고용계약서, 학력(학사↑), 경력,
  사업자등록증.")가 서류 목록인 것처럼 처리되어 "학력(", "경력" 등
  깨진 조각으로 표시됨.
- `D-5` "지국·지사의 설치허가증..." 단일 문자열이 "지국"만 별도 타일로
  분리됨.
- `K-STAR` "석·박사 통합과정·박사과정 수료생·박사후연구원 등 해당
  유형별 입증서류"가 "석", "박사 통합과정", "박사과정 수료생" 등으로
  쪼개짐.
- `F-6` "별거·이혼소송·실종·사망·혼인단절 사안은 해당 입증서류 추가
  필요"가 "별거", "이혼소송", "실종", "사망"으로 쪼개짐.
- `E-1.procedures.workplaceChange`의 "근무처변경·추가 신고서(별지
  제38호의3 서식)"도 동일하게 분리됨.

이 조각들은 번역하지 않았다 — 깨진 한국어 조각에 영어를 붙이면 버그가
가려지는 게 아니라 더 눈에 띄게 될 뿐이라 판단. `paradisoSplitDocItem`
(또는 유사 로직)의 "·"/콤마 분리 처리를 조사하는 별도 작업을 권장함
(렌더러 수정 우선 원칙에 따라, 데이터 미변경). 이 결합형("·" 포함)
용어 몇 개(`workplace_change_addition_report`,
`phd_track_evidence_by_type`, `fishery_worker_insurance`)는 용어집에
남겨두었다 — 지금은 매칭되지 않지만, 위 분리 버그가 나중에 고쳐지면
바로 작동하도록 미래 호환.

"체류민원 기준 주의"(주의 문구, 서류 아님)와 "Document definition
needed"(미해석 doc_* id 플레이스홀더)는 의도적으로 계속 제외.

### 추가 수정: Standard 구비서류 탭의 주의행 버그
조사 중 `renderDocumentTabPanel`(독립 탭 UI)이 "체류민원 기준 주의" 같은
주의 문구를 체크마크 달린 서류 타일로 잘못 표시할 수 있음을 발견 —
Easy Mode에서 이미 고친 것과 동일한 버그. 기존 `EASY_MODE_CAUTION_ROW_RE`
검사를 재사용해 Standard 탭에도 동일하게 적용(노트로 강등 또는 생략).
