# 신뢰도 저하 문구 전수 정리 — reliable sources/법령/매뉴얼 대조 (2026-06)

## 배경
사용자 요청: "내 상황에 맞는 시나리오 선택" 팝업 개선과 더불어, `수동 검토 필요`·
`자동 추출`처럼 **사용자 신뢰를 떨어뜨리는 문구**를 확인 가능한 모든 reliable
sources·법령·매뉴얼을 대조해 최대한 없애고, 남는 것은 다시 정리.

## 대조한 출처 (확인 가능 범위)
- 데이터: `visa_data.json` 전수, `data/procedure_evidence_bindings.json`(근거 바인딩),
  각 레코드 `sourceManualStatus`(verified/needsManualReview/reviewNotes).
- 법령(텍스트 보유): `docs/source-manuals/law/rule_1106_full.txt`(시행규칙 전문),
  `crosscheck/lawgokr_act_272921_articles.txt`(출입국관리법),
  `lawgokr_rule_283059_articles.txt`(시행규칙 조문), `별지서식_인덱스.txt`,
  `체류서식_빠른참조.txt`.
- 매뉴얼: `docs/source-manuals/2026-05/{stay,visa}_manual_2026_05.pdf`(각 13–15MB),
  `2026-06/stay_manual_2026_06_01.pdf`, `manual_text_2026_05/*_PrvText_TOC.txt`(목차).

## 핵심 발견 (왜 전부는 못 지우는가)
1. **공식 매뉴얼 자체가 제출서류를 "가감 가능한 보조자료"로 명시.**
   2026.5 「외국인체류 안내매뉴얼」 목차 말미 공식 문구:
   > ※ 출입국·외국인청(사무소·출장소)장은 심사를 위해 특히 필요하다고 인정되는
   > 때에는 본 매뉴얼상의 제출서류를 가감할 수 있으며, 본 안내매뉴얼은 …
   > 이해를 돕기 위한 보조자료 …

   → "관할 기관에서 최종 확인" 류 **불확실성 고지는 사실과 부합**. 이를 통째로
   지우면 공식 출처와 모순되고 사용자를 오도하게 됨(허위 확정).
2. **데이터는 설계상 대부분 "미검증(자동 추출)" 상태.** `needsManualReview=true`가
   **719건**, 근거 바인딩은 `source_confirmed 7 / limited 32 / not_applicable 3`.
   즉 프로젝트가 의도적으로 "아직 원문 대조 안 됨"을 정직하게 표시 중.
3. **원문 매뉴얼이 기계 판독 곤란.** 매뉴얼은 13–15MB 스캔 PDF이고 이 환경엔 PDF
   파서가 없으며, 과거에도 목차(4KB)만 텍스트 추출됨. 700여 레코드의 세부약호별
   제출서류를 신뢰성 있게 원문 대조하는 것은 이 환경에서 불가.
4. **내부 메모는 애초에 사용자에게 안 보임.** `sourceManualStatus.reviewNotes`의
   "…자동 추출해 procedures에 반영했습니다. 수동 원문 대조가 필요합니다."(80건)는
   `index.html`/`ai.html` 어디서도 렌더되지 않는 **유지보수용 내부 메타데이터**.

→ 결론: **검증 흉내로 고지를 일괄 삭제하면 신뢰도가 오히려 하락**(허위 확정,
CLAUDE.md "법적 정확성 단정 금지"·"OCR 자동추출을 확정으로 취급 금지" 위반).
실제로 안전하게 없앨 수 있는 것은 **정직한 고지가 아니라, 중복·자기비하성
'제작 방식' 문구**임.

### 2차(이번 커밋) — 중복 '제작 방식' 프로즈 제거
아래 문구는 **동일한 주의가 이미 다른 UI에 보존**되어 있어 중복·자기비하성으로
판단(렌더 억제). 보존처: 절차별 **출처 근거 헤더**(`getDefaultLimitationExplanation`,
예: "공식 근거는 있으나 국가·공관·개별 사정에 따라 달라질 수 있어 확정 표시하지
않습니다"), **`매뉴얼 확인 필요` 출처 칩**, **묶음 안내**("화면의 묶음은 … Paradiso
분류이며 원문 매뉴얼 표현은 자격·절차별로 다를 수 있습니다"), **빈 상태 안내**.

| 문구(요지) | 건수 |
|---|---|
| `…보수적으로 자동 추출한 제출서류입니다. … 수동 검토가 필요합니다.` | 22 |
| `…원문에서 대표 서류를 구조화했습니다. … 수동 검토가 필요합니다.` | 4 |
| `위 항목은 … 자동 추출되었으며, 세부 사안은 공식 확인이 필요합니다.` | 1 |
| `자동 추출 결과에 인접 절차 문구가 섞여 … 서류 목록은 보류했습니다.` | 5 |

근거(CLAUDE.md 허용): "동일 내용이 올바른 필드에 남아 있을 때에만 중복 프로즈
제거". 주의의 **실질(서류는 사안별로 달라질 수 있으니 관할 기관 확인)은 유지**되며,
'우리가 자동 추출했다'는 제작 메모만 제거.

## 유지 — 정직한 출처·불확실성 레이어 (삭제 불가/부적절)
- **`매뉴얼 확인 필요` 출처 칩** (needsManualReview 기반, 719) — 짧고 전문적인
  출처 신뢰도 배지. 공식 매뉴얼의 "가감 가능" 성격과 부합.
- **근거 등급 설명문** (`limited`/`source_confirmed` 등) — 차분하고 정확.
- **묶음 안내·수수료 출처 인용·"관할 기관 확인" 안내** — 사실 기반 고지.

이들은 "남는 문구"가 아니라 **있어야 하는 고지**. 없애려면 레코드별 원문 검증으로
`source_confirmed` 승격이 필요하나(아래), 승격해도 공식 매뉴얼 특성상 "수수료·
처리기간·예약 방식은 관할 기관 확인" 류 안내는 남음.

## 잔여(=후속 수동 검토 대상)와 처리 경로
다음은 **데이터 신뢰도(검증) 문제**이며 표시 문구만으론 정리 불가:

1. **`needsManualReview=true` 719건 / `limited` 32건** — 레코드별로 2026.5
   매뉴얼 해당 페이지를 원문 대조 → 제출서류 확정 → `sourceManualStatus.verified=true`,
   `needsManualReview=false`, `procedure_evidence_bindings`에 `source_confirmed`
   바인딩 추가 시 칩이 `출처 확인됨`으로 승격(보호 파일 surgical 수정 필요).
2. **`source_confirmed` 7건** — 이미 검증됨. UI에서 모순 표기 없는지만 확인하면 됨.
3. **서류 목록 공란(구 "보류" 5건)** — 자동 추출 노이즈로 목록 미구성. 매뉴얼
   원문에서 실제 제출서류를 채워야 함(공란 시 정직한 빈 상태 안내가 노출됨).
4. **법적 기준선 보조 가능**: 공통서류·신청서식(별지서식)은 출입국관리법 시행규칙
   (보유 텍스트)로 교차확인 가능 → 향후 사람 검증 시 기준선으로 활용 권장. 단,
   세부약호별 추가서류는 매뉴얼 원문이라 본 환경에서 확정 불가.

## 안전성 원칙(준수)
- 전부 **표시(렌더) 단계** 처리, 보호 데이터 파일(`visa_data.json` 등) **무변경**.
- **고지 약화·삭제 없음**: 실질 주의는 출처 헤더/칩/안내문에 보존.
- **법적 내용 신규 생성·확정 단정 없음**(CLAUDE.md 준수). 검증이 필요한 항목은
  본 문서에 잔여로 명시.
