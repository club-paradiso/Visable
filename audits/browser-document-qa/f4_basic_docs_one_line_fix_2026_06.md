# F-4 "기본 준비서류" 한 줄 나열 오류 수정 (2026-06)

## 증상 (사용자, 라이브 사이트)
F-4 비자 결과의 절차별 안내 "기본 준비서류" 섹션에서 **모든 서류가 한 줄로** 나열됨
(다른 체류자격은 서류별 체크리스트 타일로 분리 표시 → F-4만 형식이 다름).

## 원인
`visa_data.json`의 F-4 `procedures.extension.requiredDocs.requiredDocs`가 매뉴얼 PDF에서
**보수적으로 자동 추출된 하나의 콤마 결합 문자열**이었음:

```
"신청서, 수수료, 한국어능력 입증서류, 체류지 입증서류(예: 임대차계약서 …) 등 □ 재외동포(F-4) 자격 소지자의 취업"
```

- 절차 범위(procedure-scoped) 데이터가 표시 권위라서, 이 한 덩어리 문자열이 F-4의 **정상
  구조화 데이터**(`extReqDocs = [doc_app_form, doc_fee, doc_address]`, `documents_extension`
  의 `{name,note}` 행)를 가림.
- `toDocArray`의 단일 prose-blob 가드(`paradisoIsSingleProseBlob`)가 `·`+장문 조건으로 이
  문자열을 통째로 유지 → 하나의 과대 타일로 렌더됨.

## 수정 (렌더러 전용 — CLAUDE.md 준수, 보호 데이터 미수정)
`index.html`에 `paradisoSplitProcedureDocBlob()` 추가 후 `toDocArray` 문자열 분기 선두에서 호출:
- **문서 머리말로 시작하고**(신청서/여권/수수료/한국어능력 …) 최상위 콤마로 나뉘며 **모든
  조각이 문서명**일 때만 분할(괄호 안 콤마는 보존, 일반 설명문은 분할하지 않음).
- 말미의 매뉴얼 **다음 섹션 제목 조각**("… 등 □ 재외동포(F-4) 자격 소지자의 취업")은 제거.
- 맨 토큰을 **표준 doc ID로 정규화**: `신청서`→`doc_app_form`(="통합신청서(별지 제34호 서식)" —
  기존 F-4 신청서 통일 명칭), `수수료`→`doc_fee`(수수료 박스로 처리, 다른 자격과 동일).

### 결과 (F-4 체류기간 연장 "기본 준비서류")
- 통합신청서(별지 제34호 서식)
- 한국어능력 입증서류
- 체류지 입증서류*  (예시 목록은 비고로 분리)
- (수수료는 별도 수수료 박스)
→ 다른 체류자격과 동일한 체크리스트 타일 형식으로 통일, "신청서" 워딩도 통일 명칭 적용.
