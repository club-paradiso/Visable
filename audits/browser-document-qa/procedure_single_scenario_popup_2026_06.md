# 절차 시나리오 — 단일 시나리오도 화면 내 팝업으로 통일 (2026-06)

## 요청 (사용자 제안)
F-4를 검색했을 때 절차별 안내에서 "외국인등록"을 클릭하면, **각 시나리오별로 어떤 절차·서류가
필요한지 화면 내 팝업으로** 안내. (사용자 선택: **단일 시나리오도 팝업화 — 전역 적용**)

## 기존 구조 (이미 존재하던 인프라)
- 시나리오 선택 팝업(`#scenarioPickerOverlay` 패널 + `scenario-picker-trigger` 버튼 +
  `scenario-needs-pick` 표시 게이팅)이 **시나리오 2개 이상**인 절차에 이미 적용 중.
- F-4 "외국인등록"은 시나리오가 **1개**(`f-4-domestic-residence-report` 국내거소신고, 출처
  기반 서류 보유)라서 **인라인으로 직접 표시**되어 다른 절차와 동작이 달랐음.

## 변경 (`index.html` 렌더러만 — CLAUDE.md 준수)
1. `renderProcedureVariants`: **단일 시나리오 인라인 분기 제거**. 시나리오가 1개여도
   다른 절차와 동일하게 `scenario-needs-pick` 팝업 경로로 렌더 → 절차 클릭 시 인라인으로
   서류를 쏟지 않고, "내 상황에 맞는 시나리오 선택하기" 버튼 → 팝업에서 선택 → 해당 시나리오의
   절차·서류만 표시. (전 체류자격 일관 적용)
2. `applyRouteSelection`(F-4 등 경로 위저드): **광범위 경로(특정 variantId 없음)가 시나리오
   1개짜리 절차에 도달하면 그 시나리오를 자동 선택**하도록 보완 → 단일 시나리오 팝업화로 인해
   경로 선택 후 빈 상태가 보이는 회귀 방지. 시나리오가 여러 개인 광범위 경로는 기존대로 빈
   상태에서 사용자가 선택.

## 데이터/안전성
- 새 시나리오·서류를 **발명하지 않음**. 기존 출처 기반 variant 데이터를 그대로 사용,
  표시 게이팅만 변경.
- 보호 데이터 파일 미수정. 디스클레이머/출처/주의문 유지.
- 기존 팝업 인프라(포커스/ESC/외부클릭/백드롭) 재사용 — 새 모달 미추가.
