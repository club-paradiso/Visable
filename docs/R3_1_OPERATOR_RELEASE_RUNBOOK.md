# VISABLE 콘텐츠 운영 스튜디오: 릴리스 및 롤백 운영 런북
## 출입국 서류 정보 개정·검증·게시·롤백 표준 운영 절차서

- **문서 버전**: v1.1 (Milestone R3.1)
- **적용 대상**: 출입국 행정 정보 운영자, 법률 검토관, 릴리스 배포 관리자
- **운영 환경**: `https://visable.vercel.app/content-studio.html` (로컬 테스트: `http://localhost:8000/content-studio.html`)
- **최종 개정일**: 2026-10-20

---

## 1. 운영 목적 및 핵심 원칙

VISABLE 콘텐츠 운영 스튜디오(Content Operations Studio)는 비개발자 운영 인력이 소스 코드를 직접 수정하지 않고도 대한민국 647개 출입국 상황별 구비서류 안내를 안전하게 갱신하고 배포할 수 있도록 지원합니다.

### 4대 불변 운영 원칙 (Core Invariants)
1. **647개 전수 보존 원칙 (Zero Data Loss)**:
   - 체류기간 연장(224건), 체류자격 변경(251건), 외국인등록·거소신고(172건) 총 647개 상황 항목은 임의 누락이나 삭제를 전면 불허합니다.
2. **법적 근거 다차원 메타데이터 등록 (Evidence Gate)**:
   - 단순한 웹 링크(`https://`) 입력을 넘어, 발행 기관, 지침 판차, 조항 및 페이지, 시행일을 명시해야 합니다.
3. **상호 교차 검토 원칙 (Four-Eyes Principle)**:
   - 본인이 작성한 개정 초안을 스스로 승인할 수 없습니다. 독립적인 제2의 검토자가 변경사항을 확인하고 승인해야 합니다.
4. **전국 표준과 관서별 차이의 엄격한 격리**:
   - 26개 출입국·외국인관서의 자체 실무 요건은 국가 공통 기준을 변형하지 않고 독립된 관서별 오버라이드로 분리 관리합니다.

## 2. 역할별 권한 및 준비 사항

| 역할 (Role) | 주요 권한 | 필수 자격 및 인증 |
|---|---|---|
| **조회자 (Viewer)** | 647개 서류 데이터, 개정 이력, 관서별 차이 조회 | 열람 전용 토큰 (`viewer`) |
| **편집자 (Editor)** | 서류 항목 수정, 신규 개정 초안(Draft) 작성, 관서별 오버라이드 등록 | 서류 작성 담당자 토큰 (`editor`) |
| **검토자 (Reviewer)** | 초안 변경사항(Diff) 심사, 법적 근거 대조, 승인 또는 반려 | 법률 검토관 토큰 (`reviewer`) |
| **게시자 (Publisher)** | 647개 무결성 검증 실행, 후보 릴리스 생성, 운영 게시, 긴급 롤백 | 릴리스 책임자 토큰 (`publisher`) |

## 3. 표준 릴리스 6단계 워크플로우

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  1단계: 초안 작성 │ ──> │  2단계: 상호 검토 │ ──> │  3단계: 사전 검증 │
│ (Editor 작성)  │     │ (Reviewer 승인)│     │ (647개 무결성) │
└──────────────┘     └──────────────┘     └──────────────┘
                                                 │
                                                 ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  6단계: 비상 롤백 │ <── │  5단계: 운영 배포 │ <── │ 4단계: 후보 미리보기│
│ (사유 기록 원복)│     │ (원자적 파일 반영)│     │ (배너 확인 검증) │
└──────────────┘     └──────────────┘     └──────────────┘
```

### 1단계: 서류 개정안 작성 (Drafting)
1. **서류 항목 검색 및 선택**:
   - 좌측 편집기에서 체류자격 코드(예: `D-2`, `E-7-1`, `F-4`) 또는 업무 유형(`연장`, `변경`, `등록`)을 검색합니다.
2. **구비서류 입력**:
   - 쉬운 안내 명칭, 필수 제출 서류, 조건부 제출 서류, 예외 면제 조건을 항목별로 줄바꿈하여 작성합니다.
   - 본인 직접 방문 필수 여부 및 대리 신청 가능 범위를 선택합니다.
3. **공식 근거 메타데이터 입력 (필수)**:
   - **공식 근거 URL**: `https://www.hikorea.go.kr` 또는 `https://moj.go.kr` 시작 링크.
   - **근거 법령/지침 명칭**: 예) `외국인 체류관리 지침 (체류자격별 구비서류)`.
   - **발행 기관**: 예) `법무부 출입국·외국인정책본부`.
   - **지침 판차**: 예) `2026년 하반기 개정판`.
   - **해당 조항 및 문서번호**: 예) `제3장 유학(D-2) p.142~144`.
   - **시행일**: YYYY-MM-DD 형식 입력.
4. **초안 제출**: `초안 저장 및 검토 요청`을 누릅니다.

### 2단계: 변경사항 비교 및 상호 검토 (Review & Approval)
1. **검토 대기열(Review Queue) 진입**:
   - 상단 `검토 대기열` 탭에서 대기 중인 초안 목록을 확인합니다.
2. **변경사항(Diff) 비교 확인**:
   - `비교 (Diff)` 버튼을 눌러 기존 내용과 개정 내용의 차이(추가/삭제)를 확인합니다.
   - 법적 영향도 경고 안내를 점검합니다.
3. **상호 검토 승인 (Four-Eyes Principle)**:
   - 작성자와 검토자가 동일한 경우 승인이 자동 차단됩니다.
   - 다른 검토자가 내용을 최종 확인한 후 `승인 (Approve)`을 실행합니다.

### 3단계: 무결성 사전 검증 (Pre-publish Validation)
1. 상단 `게시 및 배포 (Publish)` 탭으로 이동합니다.
2. `검증 실행` 버튼을 누르고 시스템 자동 진단 결과를 확인합니다:
   - 전체 상황별 서류 전수 보존: **정확히 647개** (PASS).
   - 체류기간 연장: **224개** (PASS).
   - 체류자격 변경: **251개** (PASS).
   - 외국인등록·거소신고: **172개** (PASS).
   - 데이터 세트 무결성 체크섬(SHA-256) 생성 여부 확인.
   - 영구 보존 스토리지(Durable SQLite) 상태 확인.

### 4단계: 후보 릴리스 생성 및 공개 웹 미리보기 (Candidate Preview)
1. **릴리스 태그 및 배포 설명 입력**:
   - 릴리스 태그: 예) `rel-20261020-01`
   - 배포 요약: 개정된 출입국 지침 반영 내역 기록.
2. **후보 릴리스 미리보기 링크 확인**:
   - `https://visable.vercel.app/immigration-checklists.html?preview_release=rel-20261020-01`
3. **공개 웹 화면 검증**:
   - 브라우저 상단에 `🔍 [후보 릴리스 미리보기 모드]` 배너가 정상 표시되는지 확인합니다.
   - 외국인 사용자의 실제 화면에서 개정된 서류 목록과 조건이 정확히 노출되는지 직접 클릭하여 점검합니다.

### 5단계: 운영 배포 실행 (Publish Release)
1. 미리보기 검증을 완료한 후 `운영 게시 배포 실행` 버튼을 누릅니다.
2. 배포가 완료되면:
   - SQLite 데이터베이스의 표준 상황 레코드가 갱신됩니다.
   - 백엔드의 `/api/checklists/published` 동적 엔드포인트에 즉시 반영됩니다.
   - 정적 장애 대응용 JSON 파일(`data/immigration-checklists/*.json`)이 원자적으로 동기화됩니다.

### 6단계: 긴급 롤백 절차 (Emergency Rollback)
만약 배포 후 법령 해석 오류나 출입국 본부의 긴급 정정 고시가 발생한 경우:
1. `게시 및 배포` 탭 하단의 `릴리스 이력 관리 및 롤백` 테이블로 이동합니다.
2. 취소하고자 하는 릴리스 우측의 `롤백 (Rollback)` 버튼을 클릭합니다.
3. 롤백 사유 입력창에 상세 원복 근거(예: `법무부 2026-10-20 긴급 정정에 따른 원복`)를 작성합니다.
4. `롤백 실행`을 누르면 배포 직전의 스냅샷 데이터로 즉시 복구되며, 해당 릴리스는 `ROLLED_BACK` 상태로 영구 기록됩니다.

## 4. 관서별 특이사항(오버라이드) 관리 지침

1. 전국 26개 관서의 고유 실무(예: 제주출입국청 유학생 재정 기준 등)는 반드시 `관서별 차이 (Overrides)` 탭에서만 등록해야 합니다.
2. 관서별 오버라이드는 관서 코드(Office Code)와 자격 코드로 개별 바인딩되며, 647개 국가 표준 체크리스트의 원형 데이터를 절대로 오염시키지 않습니다.

## 5. 비상 연락 및 장애 대응 체계

- **시스템 장애 (API 500/503)**:
  - 사용자 웹사이트는 로컬 정적 JSON 파일로 자동 전환되므로 일반 외국인 사용자의 조회 서비스는 중단 없이 유지됩니다.
- **배포 실패 또는 데이터 불일치 경고**:
  - 즉시 릴리스를 중단하고, 시스템 로그 및 `reports/R3_1_API_CONTRACT_AUDIT.md`를 참조하여 데이터베이스 무결성을 확인합니다.
