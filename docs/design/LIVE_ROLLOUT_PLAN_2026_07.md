## 1. 반영 우선순위

우선순위는 **(사용자 가치 × 구현 안전성) ÷ 회귀 위험**으로 정했다.
`index.html`은 단일 파일 대규모 앱이므로, UX Lock §2 보존 계약을 넘지 않는 범위에서만 움직인다.

**공통 지침:** 마크업 구조·`id`·`data-action`은 그대로 두고 CSS와 문구만 바꾼다.

> **P1-1 반영 기록 (완료).** 대상은 대행기관·지정의료기관 파인더의 로딩·빈결과·에러다.
> 메인 검색의 빈 결과는 보존 계약이 걸린 메인 `<script>` 안에서 생성되므로 **이번 범위에서 제외**했다.

>
> **작업 중 발견한 함정 — 반드시 읽을 것.**
> `--color-surface` / `--color-text` / `--color-border` / `--color-error` 계열은
> **`[data-theme="dark"]` 에서 재정의되지 않는다.** `:root` 와 `archive_diary` 테마에만 정의돼 있다.
> 이 계열로 카드 배경을 칠하면 다크 모드에서 밝은 카드가 그대로 튀어나온다.
> 테마를 따르는 것은 `--bg0/--bg1/--bd/--t1/--t2/--ac/--cy` 계열뿐이다.
> **표면·보더·텍스트·오류색은 반드시 후자를 쓴다.** (§4 표의 매핑도 이 계열 기준이다.)

## 2. PR 단위 규칙

1. **화면 1개 = PR 1개.** 여러 화면을 한 PR에 묶지 않는다.
2. PR 본문에 대응 Figma 페이지 번호를 명시한다.
3. 변경 전후 스크린샷을 첨부한다.
4. **보존 계약(UX Lock §2) 점검을 PR마다 수행한다:**
   - `id` / `data-action` / 인라인 `onclick` 유지
   - `<body class="landing" data-theme="light">` 유지
   - `window.PARADISO_BACKEND_URL` config 스크립트 유지
   - 메인 `<script>` 블록 무변경
5. i18n 문구를 바꾸면 **14개 언어 팩 전부** 반영하고 JSON 유효성을 검증한다.
6. 리걸/이민 관련 문구·면책·출처 경고는 축소·삭제하지 않는다.

## 3. 카피 원칙 (앱인토스 UX 라이팅 기반)

- **해요체**로 통일한다.
- 능동형·긍정형으로 쓴다. ("없어요" → "~하면 할 수 있어요")
- 다이얼로그 왼쪽 버튼은 **"닫기"**. "취소"는 쓰지 않는다.
- 과도한 경어("~시겠어요?", "~께")를 쓰지 않는다.
- CTA는 누른 뒤 무엇이 일어나는지 알 수 있게 쓴다.
- **"추천" ≠ "가능"** — 자격 판단을 단정하지 않는다.
- AI 산출물은 "참고용"임을 항상 병기하고, 공식 검색 결과보다 권위 있게 보이지 않게 한다.

**주의:** 라이트 카드(`#FFFCF5`)는 배경과 명도가 가까워 **1px 보더가 필수**다.
다크의 "흰색 8%" 보더는 라이트에서 `#E6E6EE` 실선으로 대체한다.

**더 중요한 주의:** 위 표는 **목표값이지 현황이 아니다.** 현재 `index.html`의 실제 값은 다르다
(예: 라이트 보더 `--bd`가 지금은 회색이 아니라 갈색 `#998058`이다).
Figma 토큰 ↔ CSS 변수 ↔ 현재 라이브 값의 대조표는
`docs/design/FIGMA_CODE_RECONCILIATION_2026_07.md` §4.3 에 있다.
색을 옮길 때는 규칙마다 하드코딩하지 말고 **변수 값을 바꾼다.**
