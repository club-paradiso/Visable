## 1. 반영 우선순위

우선순위는 **(사용자 가치 × 구현 안전성) ÷ 회귀 위험**으로 정했다.
`index.html`은 단일 파일 대규모 앱이므로, UX Lock §2 보존 계약을 넘지 않는 범위에서만 움직인다.

**공통 지침:** 마크업 구조·`id`·`data-action`은 그대로 두고 CSS와 문구만 바꾼다.

> **P1-1 반영 기록 (완료).** 대상은 대행기관·지정의료기관 파인더의 로딩·빈결과·에러다.
> 메인 검색의 빈 결과는 보존 계약이 걸린 메인 `<script>` 안에서 생성되므로 **이번 범위에서 제외**했다.
> 그건 마크업이 아니라 스크립트를 건드려야 하는 일이라 P3에서 별도로 다룬다.
>
> **작업 중 발견한 함정 — 반드시 읽을 것.**
> `--color-surface` / `--color-text` / `--color-border` / `--color-error` 계열은
> **`[data-theme="dark"]` 에서 재정의되지 않는다.** `:root` 와 `archive_diary` 테마에만 정의돼 있다.
> 이 계열로 카드 배경을 칠하면 다크 모드에서 밝은 카드가 그대로 튀어나온다.
> 테마를 따르는 것은 `--bg0/--bg1/--bd/--t1/--t2/--ac/--cy` 계열뿐이다.
> **표면·보더·텍스트·오류색은 반드시 후자를 쓴다.** (§4 표의 매핑도 이 계열 기준이다.)

> **P1-2 는 P1 에서 착수 불가 — 실측으로 확인했다.** 두 겹으로 막힌다.
> 첫째, 체크리스트 타일은 보존 계약이 걸린 메인 `<script>` 안(`tagsHtml`)에서 생성된다.
> 진행률·저장/공유·완료 상태 UI 를 붙이려면 그 블록을 고쳐야 한다.
> 둘째, Figma 14 가 타일마다 보여주는 **발급처·조건부 표시가 현재 데이터에 존재하지 않는다.**
> 그걸 만들어 넣는 건 `CLAUDE.md` 가 금지한 "요건 신설"에 해당한다.
> 따라서 P1-2 는 **P3(스크립트 변경 트랙)** 으로 옮기고, 데이터 확장은 별도 안건으로 다룬다.

> **P1-3 반영 기록 (완료).** 계획서는 "결과 카드 CSS" 라고 적었지만 실제 원인은 더 아래였다.
> 랜딩 전반이 쓰는 **`--p-*` 팔레트가 `:root` 와 `archive_diary` 테마에만 정의돼 있고
> 기본 테마의 `[data-theme="dark"]` 에는 아예 없었다.** 그래서 다크 모드에서 섹션 제목·본문·
> 매뉴얼 카드가 어두운 잉크색 그대로 남아 어두운 배경 위에서 읽히지 않았다.
> 규칙을 하나씩 덮어쓰지 않고 **`--p-*` 다크 값만 정의**해 한 번에 해결했다.
> 이로써 다크에서 재정의되지 않는 토큰 계열은 `--color-*` 와 `--p-*` **둘 다**였음이 확인됐다.
> 새 컴포넌트를 만들 때 이 두 계열로 표면·텍스트를 칠하지 않는다.
>
> 검증: 같은 파일 2회 캡처(대조군) 라이트 변화 20.29% vs 변경 후 20.30% —
> 차이가 전부 애니메이션 캡처 노이즈이며 라이트 회귀가 없음을 확인했다.

> | 시안 레일 | 라이브 |
> |---|---|
> | 서류 선택 | `어떤 서류를 작성하시나요?` |

> 이미 있다. **UI 정비 작업은 필요 없다.**
>
> 대신 **시안 카피가 라이브보다 뒤처져 있어 시안 쪽을 갱신했다 (완료, 코드 변경 없음).**
>
> - 제목 `순서대로 채우면 서류 준비 끝!` → `필수서류 작성 도우미`.

>   공식 서식·관할 관서 확인)으로 교체.
> - **`개인정보 유출 걱정 없이 간편하게!` → 사실 고지로 교체.** 이게 핵심이다.

>   "브라우저 메모리 안에서만 사용 · 서버 전송/저장 없음 · localStorage 미사용 ·
>   PDF 는 브라우저 안에서 빈 정본 위에 직접 작성". 개인정보 카피는 단정하지 않는다.
>   필 하나였던 것을 2줄 고지 카드로 바꾸고 우측 열을 재배치했다.
>

> 한국어·영어 병기. 둘 다 라이브가 앞선 항목이므로 **라이브를 건드리지 않는다.**

## 3. 카피 원칙 (앱인토스 UX 라이팅 기반)

- **해요체**로 통일한다.
- 능동형·긍정형으로 쓴다. ("없어요" → "~하면 할 수 있어요")
- 다이얼로그 왼쪽 버튼은 **"닫기"**. "취소"는 쓰지 않는다.

## 4-A. 오로라 + 사이트 전체 가독성 패스 (2026-08)

> **New Home 다크 히어로에 오로라 도입 + 5개 페이지 가독성 교정.**

### 오로라 — 색을 새로 만들지 않았다

다크 New Home 히어로가 `var(--vp-paper)` 단색이라 완전히 평평했다.
색을 새로 고르는 대신 **이미 확정돼 있던 하우스 레시피**를 찾아서 이식했다 —
Figma page 29 `20 Waymaker ✅ 히어로` 의 **"Waymaker Hero · Dark Aurora"(`198:5`)**.

레시피의 핵심은 **"어두운 wash 톤이 아니라 밝은 accent 를 아주 낮은 알파로"** 다.
어두운 톤을 쓰면 다시 평평해진다. (재구축 당시 이 함정에 한 번 빠졌었다.)

| 레이어 | 값 |
| --- | --- |
| base | `#0E3028 → #051A15` (세로) |
| bloom-mint | `#3BE4B8` @ .15 |
| bloom-peri | `#5A63A8` @ .24 |
| bloom-ember | `#FF8B7A` @ .09 |
| bloom-glow ×2 | `#F3EEDF` @ .07 / .05 |
| 전부 | `LAYER_BLUR 190` |

- **라이브**(`assets/css/visable-product-2026.css`): 위 5겹을 `radial-gradient` 로 옮겼다.
  베이스는 아래에서 `--vp-paper` 로 착지시켜 본문과의 이음매를 없앴다.
  시안의 State A/B/C Smart-Animate 루프에 대응하는 26s 표류는 `::before` 로 분리했다
  (그래디언트 재도색 없이 transform 만). `prefers-reduced-motion` 에서는 정지한다.
- **알파 조정:** 라이브만 mint `.15→.13`, glow `.07→.06`. 시안과 달리 실제 히어로에는
  본문이 얹히는데, 원본 값이면 민트 블룸 정점에서 보조 텍스트가 4.46:1 로 기준
  미달이다. 조정 후 4.91:1. **시안(page 32)은 그 지점에 본문이 없어 스펙값 그대로 둔다.**

### 가독성 — 추정하지 않고 실제 픽셀을 measured

CSS 에서 배경색을 추정하면 그래디언트·반투명·겹침에서 틀린다. 대신 각 페이지를
두 번 렌더링했다 — 한 번은 정상, 한 번은 `-webkit-text-fill-color: transparent` 로
**글자만** 지우고(테두리·배경·currentColor 파생 페인트는 그대로). 두 번째 렌더가
진짜 배경이고, 거기서 텍스트 위치의 픽셀을 뽑아 대비를 계산했다.

5개 페이지 × 라이트/다크 = **2,536개 텍스트 런**. **425건 미달 → 0건.**

| 원인 | 전 | 후 |
| --- | --- | --- |
| 3차(muted) 잉크 — 실패의 대부분 | 라이트 3.10:1 / 다크 2.53:1 | 4.6:1↑ |
| 다크 블록이 `--t1/--t2` 로 연결 안 됨 | 페이지 인라인 토큰이 그대로 | 라이트와 대칭 |
| 밝은 민트 위 흰 글자 (버튼·칩 라벨) | 1.62:1 | 6.9~8.0:1 |
| `ai.html` 라이트 `--p-emerald-soft` | 1.87:1 | 5.29:1 |
| `ai.html` 라이트 `.char-counter` | **1.00:1** (안 보임) | 7.4:1 |
| 브랜드 브릿지 히어로 부제 | 2.67:1 | 4.66:1 |
| "공식 사이트 확인" 주의 배지 | 2.58:1 | 4.69:1 |

**주의 문구는 약화하지 않았다.** 경고 배지는 문구를 그대로 두고 더 잘 보이게만 조정했다.

**측정 하네스 자체의 오탐 3건을 걸러냈다** — 스크롤 리빌로 `opacity:0` 인 요소,
`background-clip:text` 그래디언트 글자, 그리고 Chromium 이 일부 색을
`color(srgb …)`(0–1)로 보고하는데 `rgb()`(0–255)로 파싱한 것. 마지막 건은 크림색을
검정으로 읽어 실패를 크게 부풀렸다(`ai.html` 라이트가 35건 → 실제 10건).
**하네스가 "고장났다"고 말하기 전에 하네스부터 의심할 것.**

### Waymaker 풀랜딩 (`369:12`) — 별도 페이지로 만들지 않고 `ai.html` 에 접었다

먼저 시안대로 `waymaker.html` 을 만들었다가, **같은 PR 안에서 걷어내고
`ai.html` 로 통합했다.** 만들고 나서야 분명해진 게 있어서다.

**`ai.html` 이 곧 Waymaker다.** `<body class="product-waymaker">`, 타이틀도
"Waymaker by Paradiso". 파일명만 레거시다. 그래서 랜딩은 도구와 겹쳤다 —

| 랜딩 요소 | `ai.html` 에 이미 있던 것 |
| --- | --- |
| 프롬프트 입력창 | 컴포저 입력창 |
| 기능 카드 6장 중 **5장** | 좌측 레일 Ask · Plan · Sources · Forms |
| 브랜드 소개 문단 | 웰컴 메시지 + 예시 칩 4개 |

카드 6장 중 레일이 못 덮던 목적지는 **귀화면접 학습실 하나뿐**이었다.
그 하나를 위해 페이지를 따로 두면 도구로 가려던 사람에게 클릭만 하나 늘고,
브랜드 문구를 두 곳에서 관리해야 한다.

**그래서 접었다.** 랜딩에서 진짜 새로운 것 두 가지만 도구로 옮겼다:

1. **브랜드 락업** (`waymaker.` + "막막하지 않게, 명쾌하게.") — 웰컴 메시지 위.
   `.msg-bubble` **바깥**에 둔다: 언어 전환 시 버블은 `innerHTML` 이 통째로
   교체되므로 안에 넣으면 지워진다. ko/en/zh 3개 언어 모두 번역했다.
2. **레일 5번째 링크** `Practice · 귀화면접 학습실` — 유일하게 비어 있던 목적지.

**오로라 — 처음엔 포기했다가, 웰컴 상태 한정으로 되살렸다.**

처음엔 계약(*"Aurora is hero-background only — result, document and source
screens stay calm"*)을 근거로 아예 넣지 않았다. 그런데 그 판단이 과했다.
계약이 조용히 두라는 건 **결과·서류·출처를 읽는 화면**이지 이 페이지 전체가
아니다. 그리고 `ai.html` 의 **웰컴(빈) 상태는 기능적으로 히어로다** — 아직
결과가 없고 진입하는 순간이다.

그래서 **웰컴 상태에서만** 오로라를 띄우고, **첫 메시지가 붙는 순간 걷는다**
(`appendMsg` 에서 `body.wm-conversing` 부여 → 0.7s 페이드 아웃). 절차
내비게이터(`.wm-active`)는 작업 화면이라 처음부터 띄우지 않는다. 이러면 계약의
취지("읽는 화면은 calm")를 지키면서 브랜드 표현도 살아난다.

구현 함정 하나: 오로라 레이어는 `z-index:-1` 이라 body 배경 위·본문 아래에
깔리는데, `.wm-workspace-shell` 이 불투명 배경을 `!important` 로 덮고 있어
전부 가려졌다. 웰컴 상태에서만 그 표면을 비우는 규칙을 스킨에 추가했다
(특정도: 원본 (0,3,1)+!important 를 `:not()` 두 개로 (0,4,1) 로 이긴다).
첫 메시지가 붙으면 불투명 표면이 그대로 돌아온다.

`?q=` 프리필도 함께 걷어냈다. 랜딩이 유일한 호출자였고, 남겨 두면 아무도
쓰지 않는 코드 경로가 된다.

> **확정 시안을 따르지 않은 결정이다.** `369:12` 은 ✅ 확정이지만, 실제로 만들어
> 보니 대부분이 도구와 중복이었다. P2-5(준비상태 체크)·P2-7(서류 작성 도우미)에서
> 이미 쓴 것과 같은 판단 — **"시안이 확정이어도, 라이브가 이미 그 일을 하고 있으면
> 옮기지 않는다."** 시안 프레임은 지우지 않고 Figma 에 결정 노트를 붙여 뒀다.

**검증:** 5개 페이지 × 라이트/다크 재측정 0건 미달, 레일 5개 링크 목적지 확인,
ko/en/zh 전환에서 락업이 살아남고 번역되는 것 확인, `?q=` 무시 확인,

## 4-D. ⚠️ 공통 CSS 를 고쳤으면 캐시버스터를 반드시 올린다

5개 공개 페이지는 공통 스킨을 **쿼리 문자열 버전**으로 참조한다.

```html
<link rel="stylesheet" href="assets/css/visable-product-2026.css?v=YYYYMMDD-slug">
<link rel="stylesheet" href="assets/css/waymaker-workspace.css?v=YYYYMMDD-slug">
```

**파일을 고치고 `?v=` 를 그대로 두면 URL 이 같아 브라우저·CDN 이 예전 CSS 를 계속
쓴다.** 실제로 그 사고가 났다 — `#557`·`#558`·`#559` 가 스킨에 72줄을 넣는 동안
`?v=` 는 `#539` 이후 그대로였다.

특히 위험한 이유: **`index.html` 은 그 세 PR 에서 자기 파일이 0줄 바뀌었다.**
주 CTA 대비·가독성 토큰·오로라용 shell 투명화가 전부 공통 CSS 에만 있으므로,
캐시된 CSS 로는 페이지가 **바이트 단위로 동일**하다. 배포는 성공했는데
"아무것도 안 바뀌었다"로 보인다.

**규칙:** `assets/css/*.css` 를 건드린 PR 은 참조하는 모든 HTML 의 `?v=` 를 같이
올린다. 확인 명령:

```bash
grep -ho 'visable-product-2026\.css?v=[^"]*' *.html | sort -u   # 값이 하나여야 한다
git log --oneline -1 -- assets/css/visable-product-2026.css      # 이 커밋 이후 ?v= 가 바뀌었는지
```

**배포 여부와 캐시 문제를 헷갈리지 말 것.** 이번 건은 GitHub Pages 배포가 머지마다
전부 성공(`pages-build-deployment`)한 상태였다. 파이프라인을 의심하기 전에
`?v=` 부터 본다.

라이브는 좌측 카피 + 우측 가이드 카드의 2단 그리드였고, 확정 시안은 중앙 정렬
단일 컬럼이다. 카피·레이아웃·오로라·키네틱 스트립·각주·오로라 도트를 전부 옮겼다.
블룸 값은 Plugin API 로 직접 읽었다.

| 레이어 | 색 | 알파 | 블러 |
|---|---|---|---|
| base | `#FFFBF3` → `#F3E9DA` (180deg) | — | — |
| bloom-coral | `#FF6B5B` | .28 | 180 |
| bloom-peri | `#7F89CE` | .30 | 180 |
| bloom-emerald | `#0EA37B` | .15 | 180 |
| bloom-light-1 | `#FFFCF5` | .50 | 180 |
| bloom-light-2 | `#FFFFFF` | .35 | 180 |

**시안과 의도적으로 다르게 간 3곳 (전부 근거 있음):**

1. **CTA** — 시안 `#085E48` + `#F3EEDF` 는 6.70:1(AA). §5 의 하우스 AAA 토큰
   `--vp-cta`/`--vp-on-cta`(7.08:1)를 쓴다. 색차는 육안 구분이 안 되는 수준이다.
2. **키네틱 스트립 잉크** — 시안 `rgba(58,84,76,.5)` 는 페리 블룸 위에서 2.29:1.
   12px 본문 크기라 그대로는 읽히지 않아 `#47594F`(5.01:1)로 올렸다.
3. **히어로 각주** — 시안 `rgba(90,101,97,.9)` 는 11px 에서 4.12:1. 3차 잉크
   토큰(`#5A6561` / `#BBC7C3`, 5.04:1)을 쓴다.

**옮기지 못한 것 1건:** 워드마크 벡터(`203:13`)는 이 실행 환경의 네트워크 정책이
figma.com 자산 호스트를 차단해 내려받지 못했다. 임의로 다시 그리지 않고 비워
두었다 — 자산을 받을 수 있는 환경에서 채워야 한다.

**주의문 관련:** 히어로의 `.nh-notice` 는 스킨이 이전부터
`display:none !important` 로 감추고 있었고, 같은 문구가 푸터(`footer.notice`)에
그대로 남아 있다. 이번 변경으로 새로 약화된 주의문은 없고, 시안의 각주
고지문이 히어로에 새로 추가됐다.

### 7-D. 검증 방식 (이번부터 고정)

1. **픽셀 프로브** — 계산이 아니라 실제 렌더 픽셀을 읽어 오로라가 보이는지 확인한다.
   "computed opacity 가 1이다" 는 증거가 아니다 (#558 에서 이 방식으로 놓쳤다).
2. **대비 재감사** — 5페이지 × 라이트/다크. 출력 JSON 이 비어 있지 않은지 먼저 본다.
   실행이 실패해 0건이 나온 것을 "미달 0건"으로 읽으면 안 된다.
3. **캐시 버스터** — 공유 스킨을 건드리면 5개 페이지 `?v=` 를 반드시 함께 올린다.
