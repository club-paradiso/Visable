# Form Helper 2.0 — how it works and how to add a form

`form-helper.html` is a data-driven page: everything the user sees, previews and downloads comes
from two JSON files and one engine.

| Piece | Path | Role |
| --- | --- | --- |
| Definitions | `data/form_definitions.json` | steps, fields, conditions (`showIf`/`reqIf`), mapping to overlay keys, derived values, validation rules, search terms, task groups, Waymaker prefill |
| Schemas | `data/form_schemas.json` | per template: official name/basis, PDF path, `template` block (sha256, bytes, pages, size, revision, verification, field-map version, anchors), `support` block (status, reason, qa), `fields` (official cell inventory), `overlay` (coordinates) |
| Engine | `assets/js/form-engine.js` | no DOM; values → overlay values → drawing ops; validation; text fit; glyph check; search. Runs in the browser and in Node |
| App | `assets/js/form-helper-app.js` | screens, editor, canvas preview, pdf-lib export, i18n (`fh.*` in `data/i18n/*.json`) |
| Inventory | `data/forms_inventory.json` + `docs/forms_official/FORM_HELPER_COVERAGE_20260923.md` | generated by `scripts/forms/build_forms_inventory.py` from the rule text; `--check` asserts freshness |
| Guard | `scripts/check_form_helper.mjs` | inventory/exclusions, template drift, schema ↔ definitions, engine unit tests, Node export of every sample verified with `scripts/forms/verify_export.py` (PyMuPDF), static geometry audit of every overlay with `scripts/forms/audit_overlay_geometry.py` (PyMuPDF) |
| E2E | `tests/e2e/form-helper.spec.mjs` | real-browser workflow, exclusions, fit warnings, editions, languages, keyboard |

## Coordinate conventions (overlay)

PDF points, origin top-left, `y` is the text **baseline** (PyMuPDF convention; the exporter converts
to pdf-lib's bottom-left origin). Entry kinds:

* text: `{x, y, size, maxWidth, lines?, lineHeight?, align?: 'center', page?, wbox?}` — `maxWidth`
  is required (without it the engine lets text run to the page edge across neighbouring cells
  and never flags it); `align: 'center'` makes `x` the centre of the writable area
* check: `{cx, cy, check: true, s?, page?}` — a vector tick centred on the printed `[ ]`
* digits: `{x, y, size, maxWidth, digits: {cells: [...centres], y, size}}` — one digit per
  printed cell when the value has exactly that many digits, otherwise the plain text run

Text fitting: shrink in 0.5 pt steps to 6.5 pt; wrap when `lines > 1`; otherwise clip inside the cell
and flag `OVERFLOW`. Characters outside `assets/forms/fonts/NanumGothic-Regular.charset.json`
leave the cell blank and flag `FONT`. A value that had to shrink to 7 pt or less is flagged
`SHRUNK` ("인쇄 확인"): some official cells are simply narrow (a mobile number in the 2 cm
phone cells of 별지 제34호서식, a long nationality name), and the user is told instead of the
text silently crossing into the next cell.

### Where a value goes (geometry rules)

The writable area of a text overlay is `[x, x + maxWidth]` (centred on `x` for `align: 'center'`)
times the glyph band of each line (0.80 em above to 0.14 em below the baseline). The audit
(`python3 scripts/forms/audit_overlay_geometry.py [F01 …] [--json]`) fails when that area

* contains a vertical table rule — solid, drawn as touching pieces, or dotted (runs of short
  dashes or of 0.6 pt dots are merged into one rule),
* is cut by a horizontal rule,
* overlaps printed template text (labels, units, 년 / 월 / 일, brackets), unless the text sits
  under the overlay's own `wbox`,
* sits glued to a label (less than 1.5 pt under it, or a label tail running into its start —
  inline slots after ':' or '(' are exempt),
* runs past the end of its table row (several templates have no outer side border: the row ends
  where its top and bottom rules end),
* or has no `maxWidth` at all.

`python3 scripts/forms/suggest_overlay_cells.py F01 [key …]` lists, per overlay, the free slot
holding the anchor, the next slot to its right and the row's vertical middle, measured from the
PDF's own vector geometry. Conventions that follow from the templates: a value goes in the empty
cell right of its label cell, not after the label text inside it (신청일, 전화번호, 휴대전화,
국적, 여권 유효기간, 연 소득금액, 직업, 전자우편 …); where a cell has a header line and an empty line
under it (성 / 명 and 년 / 월 / 일 on 별지 제34호서식 and its editions, 재외동포 별지 제1호서식), the value
goes centred in the empty line and the printed header — including the `yyyy / mm / dd` format
hints — stays visible; digit grids get one centred digit per printed cell.

## Adding a form

1. Extract the template from the official PDF:
   `python3 scripts/forms/extract_official_form.py --pages 185 --out assets/forms/pdf/F16.pdf`
   (prints sha256 / pages / size). Refugee and departure-deadline annexes are excluded by policy.
2. Dump geometry: `python3 scripts/forms/inspect_form_page.py assets/forms/pdf/F16.pdf 0` (words +
   rule lines + a 25 pt grid PNG) and `python3 scripts/forms/bracket_centers.py assets/forms/pdf/F16.pdf`
   (centres of printed `[ ]` boxes).
3. Author `forms.F16` in `data/form_schemas.json` (`fields`, `overlay`, `template`, `support`) and a
   sample in `tests/fixtures/form_overlay_samples.json`; render it:
   `python3 scripts/forms/render_filled_sample.py F16 /tmp/out` and look at the PNG.
4. Author `forms.F16` in `data/form_definitions.json` (steps, fields with `map`, search terms,
   explain copy in KO + EN — only what the form itself or the local guidance data says) and a
   field-level sample in `tests/fixtures/form_field_samples.json`.
5. Pre-render the preview background: `assets/forms/preview/F16-1.png` (scale 1.5, grayscale).
6. `python3 scripts/forms/audit_overlay_geometry.py F16` must report 0 issues, then
   `node scripts/check_form_helper.mjs --record-qa` — writes `support.qa` (PASS needs both the
   verified export and a clean geometry audit); set `support.status` to `SUPPORTED` only when qa
   is `PASS` **and** the edition check below is `VERIFIED_CURRENT`; then
   `python3 scripts/forms/build_forms_inventory.py`.
7. Run the E2E and `bash scripts/check_repo.sh`.

## Support definition

A form is SUPPORTED only when: the official source is identified and the template's printed revision
recorded; every cell is mapped; entry, preview and export run through the same ops; the Node export
is verified span-by-span; every overlay passes the geometry audit; the mobile flow works; **and**
the template edition was compared with the text currently in force (`template.verification =
VERIFIED_CURRENT`). Anything else that is mapped is PARTIAL (today: F06, whose HiKorea edition
could not be compared). `scripts/check_form_helper.mjs` enforces the rule.

### Edition check (`template.verification`)

For statute forms the annex currently in force is read from law.go.kr through its Open API
(`get_annexes` on the law's current MST; 출입국관리법 시행규칙 MST 289833, in force from
2026-09-15; 재외동포법 시행규칙 MST 267499, in force from 2025-02-01). `VERIFIED_CURRENT` is recorded
only when the header revision tag printed on the current annex equals the one on the template
(digits compared) and the row / cell structure matches; the record keeps `verifiedAgainst` =
{source, law, mst, inForceFrom, annex, headerOnCurrentText, checkedOn, method,
pendingAmendment}. Both rules carry an amendment promulgated but not yet in force (법무부령
제1125호 / 제1124호, effective 2027-09-16): re-run the check on that date and re-extract any
annex it changed. HiKorea forms (F06) stay `PENDING_HIKOREA` until the current HiKorea file can
be compared.
