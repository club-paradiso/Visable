## 0. 시작 전 감사 (브리프 10문항)

최신 main(`dce3dc0`)에서 실제 구조를 확인했다. 브리프가 지목한 파일 중
`scripts/enforcement-ui.mjs`, `lib/enforcement-fallback.js`,
`scripts/check_enforcement_ui.mjs`는 존재했고, 선행 작업으로 **PR #761**
(사전허가/사후신고 safeguards)과 **PR #763**(법령 코퍼스)이 이미 머지된
상태였다. 즉 출발점은 "금액을 함부로 표시하지 않는 fail-closed 골격 +
검증된 법령 코퍼스"가 있는 상태였고, 이번 작업은 그 위에 **사실 기반 자동
판별**을 올린 것이다.

1. **위반 유형 추출**: 백엔드 `enforcement_service._classify_violation`(정규식)
   + AI 추출(병합 시 결정론적 결과가 우선), JS 폴백 `lib/enforcement-fallback.js`에
   동일 로직 미러. 조문 표지가 명시될 때만 확정하고, 겹치면 후보만 남긴다.
2. **사전허가·사후신고 입력 방식(기존)**: 사용자가 확인 단계에서
   "사전허가 대상인지 사후신고 대상인지 확인하셨나요?"에 직접 답해야 했고
   (`workplaceRegime` = PERMIT/REPORT, 사용자 확인 전제), 모르면 건너뛰고
   금액은 보류됐다. **법률지식이 없는 사용자는 답할 수 없는 질문**이었다.
3. **workplaceRegime의 영향(기존)**: REPORT면 범칙금 계산 중단(UNSUPPORTED),
   PERMIT가 아니면 금액 미산출(MISSING_FACTS), PERMIT면 조건부 계산.
4. **체류자격만으로의 잘못된 추론**: `_report_proviso_applies`가 E-1~E-7
   (또는 자격 미상)이라는 이유만으로 "신고 단서 가능성"을 켜서 금액을
   막았지만, 반대로 신고 대상이라고 확정하지는 않았다. 다만 판별 자체는
   전적으로 사용자 확인에 의존했다.
5. **신고 대상에 범칙금표 오적용 가능성**: #761 이후 백엔드·JS 모두
   차단돼 있었다. 이번 작업에서 REPORT 전용 과태료 트랙으로 정식 분리했다.
6. **"잘 모르겠어요" 선택 시(기존)**: 해당 질문을 건너뛰고 분석은 진행되나
   MISSING_FACTS로 금액 없이 끝나며, 무엇을 확인하면 되는지 구체적
   안내는 없었다.
7. **위반 유형 선택만으로 미허가 확정되는 코드 — 실재했다.** UI
   `applyClarification`에서 `UNAUTHORIZED_WORKPLACE_CHANGE_ART21_1` 선택 시
   `workplaceChangeAuthorized=false`와 `authorizationObtained=false`를
   자동 설정했다. 근무처를 옮겼다는 사실만으로 미허가·미신고가 확정되는
   구조였다. **이번 작업에서 제거했다**(아래 P0).
8. **프런트/백엔드 불일치 가능성**: Python과 JS가 같은 규칙을 별도 구현으로
   미러링하는 구조라 상시 위험이 있다. 이번 작업은 **공유 픽스처 20건을
   양쪽 엔진에 재생**하는 패리티 체크로 고정했다.
9. **사건 당시 법령 미검증 시 오금액 위험**: 기존 스냅샷 해석은 검증된
   기간(2026-01-23~) 밖이면 `HISTORICAL_RULE_UNAVAILABLE`로 멈추고,
   기간 중 개정이 걸치면 계산하지 않는다. 고시에 대해서는 이번 작업에서
   2020-06-22 시행 전 사건을 UNRESOLVED로 추가 차단했다.
10. **불필요한 법률 용어 노출**: 확인 질문 자체가 "사전허가/사후신고"라는
    법률 분류를 사용자에게 요구했다. 사실 질문(평문)으로 교체했다.

## 1. 변경 사항

### P0 — 법률을 몰라도 이용할 수 있는 UX

- **직접 분류 질문을 기본 경로에서 제거.** `scripts/enforcement-ui.mjs`의
  확인 단계는 근무처 사건에서 다음 **사실 질문**을 하나씩 제시한다(평문,
  전부 "잘 모르겠어요" 건너뛰기 가능, 건너뛴 사실은 unknown 유지):
  변경 방식(그만두고 옮김/다니면서 추가/같은 회사 장소만) → E-7이면
  직종코드 → 이전 고용 종료 사유(계약만료/중도퇴사/본인귀책 해고/회사
  사정/폐업/기타) → 본인귀책·중도퇴사인 경우에만 원 고용주 동의 여부 →
  외국인등록 여부 → 새 근무처 자격요건 → 실제 근무 시작 여부 → 출입국
  절차(허가 받음/신고함/대기 중/아무것도 안 함).
- **관할관서 확인 질문은 최후 수단으로만** 남겼다(사실 질문을 모두 거친
  뒤에만 표시). 선택 시 `workplaceRegimeSource='USER_CONFIRMED'`로
  출처를 기록한다 — 엔진 판별과 절대 섞지 않는다.
- **자동 확정 버그 제거**: 위반 유형에서 근무처 변경·추가를 골라도
  `workplaceChangeAuthorized`/`authorizationObtained`를 더 이상
  false로 설정하지 않는다(선택지 문구 자체가 "허가 없이"를 명시하는
  제20조·제18조제1항 항목은 기존 동작 유지 — 문구에 명시된 사실의 기록).
- **상태 확장**: `PERMIT / REPORT / NOT_APPLICABLE / UNRESOLVED` +
  메타데이터(판별에 쓰인 사실, 미확인 사실, 적용 규칙, 확인한 적용제외,
  적용 법령 버전, 근거 출처, 경고, 다음 질문, 사람 검토 사유, 의무위반
  성립 여부, 신고기한·적시성, 과태료 법정 상한)를 `WorkplaceDetermination`
  모델로 정의했다.
- **결과 화면**: 판별 카드 신설 — 판별 결과와 상태(고시 판별/사용자 확인
  전제/사실 부족/위반 아님), 쓰인 사실, 확인한 요건·적용제외, 아직 확인할
  사항과 확인 방법(외국인등록증·계약서·허가서·접수증·☎1345), 공식 출처
  링크와 시행일, "참고 분석이며 공식 처분 확정이 아님" 명시.
  UNRESOLVED면 가능한 두 경로(범칙금 기준/과태료 상한)를 **금액 확정 없이**
  조건부로만 비교한다. 답변을 수정하면 분석 지문(fingerprint)에 새 사실
  필드가 포함돼 기존 계산이 즉시 무효화되고 재분석된다.

### P1 — 법령 기반 자동 판별 엔진

- **규칙 저장소** `backend/data/enforcement/workplace_regime_rules.json`:
  코퍼스의 공식 스냅샷(국가법령정보센터)에서 확인된 문언만 구조화 —
  법무부고시 제2020-212호(시행 2020-06-22, 원문 해시
  `a0d716bc…f5c15e031dfaed729c848` — 코퍼스 메타데이터 기록값),
  출입국관리법 제21조·제100조제1항제3호, 시행령 제26조의2.
  출처·시행일·검증 상태(`VERIFIED_OFFICIAL_SNAPSHOT`, 2026-11-04 확인)를
  해석과 분리해 기록했다.
- **결정론적 엔진** `backend/services/enforcement_workplace.py` +
  JS 미러 `lib/enforcement-workplace.js`. 고시 요건을 순서대로 검사한다:
  ① E-6-2는 적용제외 → PERMIT 확정 ② E-7은 직종코드로 적용제외 검사
  (제외 코드 2351·2395·285·31215·441·3991·3922·S3922·6301·7430·S740·
  S610·S700; 2742는 해외 온라인상품판매원인 경우만 제외라 상세 불명이면
  UNRESOLVED) ③ 외국인등록 요건(본인 귀책 없는 해지 시 등록 전 1회 신고
  허용 단서 포함) ④ 새 근무처 자격요건 ⑤ 본인귀책 해고·중도퇴사 +
  이적 동의 없음이면 적용제외 → PERMIT. 하나라도 불명이면 확정하지 않고
  **어떤 요건이 미확정인지**를 돌려준다. E-1~E-7이라는 이유만으로, E-7
  세부코드만으로 확정하는 경로는 없다.
- **사실/의무/위반 분리**: 판별(regime)과 별개로 의무위반을 평가한다.
  허가를 받았으면 PERMIT이어도 위반 아님(NOT_APPLICABLE), 기한 내
  신고했으면 REPORT이어도 위반 아님, 실제로 근무를 시작하지 않았으면
  어느 쪽이어도 NOT_APPLICABLE. 신고 적시성은 변경일부터 15일로 계산한다.
- **범칙금/과태료 분리**: PERMIT 확정 + 위반 성립 시에만 기존 별표 7
  범칙금표로 계산한다. REPORT는 신규 상태 `ADMINISTRATIVE_FINE_TRACK`으로
  분리하고, 검증된 법정 상한(200만원 이하)만 "상한"으로 표시한다 —
  **과태료 양정기준은 검증된 공식 자료가 없어 산정액을 만들지 않는다.**
- **AI/결정론 분리**: AI 추출 프롬프트에 근무처 사실 필드를 추가하되
  "근무처 이동만으로 절차 누락을 단정하지 말 것, regime을 출력하지 말 것"을
  명시했고, `_parse_ai_case`에서 AI가 보낸 regime 필드는 강제 제거한다.
  사용자 확인과 엔진 판별이 충돌하면 엔진 판별을 우선 표시하고 충돌을
  경고한다. 서술 기반 사실 추출(직종·종료사유·동의·등록·절차)은
  Python/JS 양쪽에 보수적 정규식으로 추가했다 — 애매한 "해고됐다"는
  귀책 여부를 단정하지 않는다.

### P2 — 증빙·설명가능성·품질

- **증빙**: 신규 업로드 인프라는 만들지 않았다(브리프 원칙). 대신 판별
  카드의 "아직 확인할 사항"마다 확인할 서류(외국인등록증, 고용계약서,
  계약종료 확인 자료, 허가서, 신고 접수증)와 기관(관할 관서·☎1345)을
  안내하고, 문서로 확인한 사실은 사실 질문에 그대로 입력해 전체 흐름을
  수동 입력만으로 완주할 수 있다. 문서에 없는 사실의 추측 경로는 만들지
  않았다.
- **개인정보 버그 수정(기존 결함)**: PII 탐지 정규식이 `\b` 경계에 의존해
  한국어 조사가 붙은 식별자(`010-1234-5678이고`, `M12345678입니다`)를
  **탐지하지 못하고 있었다**. Python/JS 모두 lookaround 패턴으로 교체했다.
- **"신고하지 않았다" 분류 누락 수정**: 서술에 "신고하지 않았고"만 있으면
  위반으로 분류조차 되지 않던 문제를 Python/JS 분류기에 동일하게 반영했다.
- **품질**: 프런트/백엔드 패리티(공유 픽스처), 날짜·기한 경계(15일,
  고시 시행일, 법령 스냅샷 경계), unknown≠false, 잘못된 상태값은
  pydantic Literal로 거부, 분석 지문 확장으로 stale 결과 차단(기존
  analysisSequence 경쟁 방지와 함께 동작).
