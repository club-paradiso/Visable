**4. How are law names and identifiers normalized?** There are three different regimes. (i) `/api/ask` planner: fixed Korean anchors per intent reason [CODE law_grounding.py:161-187] plus law names extracted from citations; deduplication by whitespace-stripped, lower-cased name + id + serial + article [CODE law_grounding.py:284-305]. A user citation must match the result name exactly, ignoring whitespace [CODE law_grounding.py:330-334]. There is no alias resolution, so "출입국법 제18조" is not resolved. (ii) Research path: `law_query_normalizer` (NFC normalization, folding of wide spaces and dashes, `§`→`제`, typo map, interpunct folding, a 22-entry immigration alias table, keyword stripping, a "loose match" name guard, relevance ranking, hierarchy level) [CODE law_query_normalizer.py:131-148, 176-282, 382-466, 516-552]. Its attribution header says it was ported from korean-law-mcp (MIT). (iii) Cloud fallback: compacts to alphanumeric/Hangul and lower case, and seeds from 10 core law names [CODE law_cloud_fallback.py:28-57, 74-94]. Identifiers: `법령ID→law_id`, `법령일련번호|MST→law_serial_no`, `reference = law_id or serial` [CODE law_tools.py:382-399]. The detail lookup sends `MST` whenever the value is all digits [CODE law_tools.py:924-927]. If only the zero-padded `법령ID` is available (for example "001386"), it would be sent as `MST` (INFERRED edge case; the serial is normally preferred at law_tools.py:915 and law_grounding.py:349-352). The JS normalizer strips spaces and `·` but not `ㆍ` [CODE enforcement-law-grounding.js:99-101]. VERIFIED.

**9. How are law citations parsed?** Four regex families, with no shared parser. (a) `citation_verifier._CITATION_PATTERN`: a Hangul run ending in `법`, optional `시행령/시행규칙`, `제N조(의M)`. It drops 항/호, does not match names ending in `법률`, and does not handle "같은 법" [CODE citation_verifier.py:7-40]. This is the parser used for user-question citations on `/api/ask` [CODE law_grounding.py:214-218, 316]. (b) `statute_citation_guard`: brackets, names ending in `법률|법|령|규칙|규정`, 항 (including ①), 호, article title in parentheses, and carry-forward of the law name for a bare `제N조` [CODE statute_citation_guard.py:58-166]. (c) `law_citation_guard._ARTICLE_RE`: article tokens with no law name, plus `별표` [CODE law_citation_guard.py:21-44]. legal_synthesis reuses this one [CODE legal_synthesis.py:29, 502-504]. (d) The research normalizer's name pattern [CODE law_query_normalizer.py:431-437]. Case numbers are handled separately [CODE citation_verifier.py:176-196]. VERIFIED.

**10.
