# Artemis v2 기초 매뉴얼 QA 프로토타입 구현 계획

2026-10-26 · 설계/실험 준비. 학습·증류·외부 모델 호출·운영 배포는 이번 범위 밖이다.
구현 경로는 experiments/waymaker-ai의 로컬 CLI로 시작하고 공개 /api/ask에는 연결하지 않는다.
초기 답변은 검색된 원문 구간과 결정적인 설명 템플릿으로 구성한다.

## 1. 입력·분류 계약

입력: question, language, 선택적 payload_status_code, reference_date.
분류 결과: status_code, subcode, current_status, target_status,
procedure_fine(16개), procedure_coarse(동등한 경우만), candidates,
missing_facts, source_domain. 명시적 세부 코드는 보존한다.
구문상 코드 인식과 실제 자격의 존재·적용 가능성은 별도 필드로 관리해야 한다.
미등록 코드·다중 절차·불분명한 전환·여권 자체 발급은 확인 질문 또는 범위 밖으로 보낸다.

## 2. 검색·근거 계약

기존 manual_registry/manual_search/manual_evidence의 읽기 전용 기능을 재사용한다.
승인 판본의 source_id·원본 SHA-256·쪽·앵커·domain·edition_approval와
개별 문단의 content_review 상태를 별도로 전달한다.
판본 선택 승인을 모든 내용의 검증으로 해석하지 않는다.
체류·사증 도메인을 분리하고 동일한 subcode를 우선한다.
부모 항목은 적용 범위가 명시된 경우만 사용하며 형제 subcode의 서류를 상속하지 않는다.
국적 등 현재 매뉴얼 검색으로 뒷받침되지 않는 질문은 근거 없음으로 처리한다.
F-4 고시 번호 충돌과 법령의 본문 검토 대기는 증거 객체의 blocking_warnings로 전달한다.
법령 헤더의 신원 확인만으로 해당 조문·서식의 유효성이나 사건 적용을 확정하지 않는다.

## 3. 답변 계약

출력 모드는 lookup / clarify / abstain / escalate.
lookup은 짧은 설명, 원문 발췌, 자료명·판본·쪽, 적용 범위와 미확인 사항으로 구성한다.
답변의 claims 배열은 각각 evidence_id와 source_span을 가져야 한다.
근거 없는 기한·금액·서류 이름은 생성하지 않는다.
초기 다국어 모드는 검수된 UI 문구와 원문을 함께 표시한다.
법률 의미의 번역이 검수되지 않았다면 자동 번역문을 공식 원문으로 표시하지 않는다.
원문은 불변이며, 검색 요약·번역·충돌 주석은 별도 값으로 보관한다.
모델 공급자는 교체 가능한 비활성 어댑터 계약만 정의하고 실제 호출하지 않는다.

## 4. 구현 순서와 완료 조건

| 순서 | 제안 파일/산출물 | 완료 조건 |
|---|---|---|
| 1 | experiments/waymaker-ai/waymaker_ai/manual_qa/contracts.py | 입력·분류·검색·claim 객체와 보류 사유의 스키마. 코드 존재 여부와 인식 결과 분리. |
| 2 | manual_qa/retrieve.py | 고정된 공개 매뉴얼 스냅샷에서 domain/subcode/approval/conflict 필터. 네트워크 차단 테스트. |
| 3 | manual_qa/answer.py | 원문 인용 기반 템플릿 답변과 결정적 보류. 추측 서류·금액·기한 생성 0건. |
| 4 | manual_qa/cli.py | 입력 JSONL → 분류/검색/답변을 각각 저장. 원문 해시와 실행 버전 포함. 사용자 질문 저장은 기본 비활성. |
| 5 | 평가 문서와 검수 명부 | 분류 평가와 QA 평가를 별도 집계하고 소유자가 승인한 결과만 다음 단계에 사용. |

## 5. 평가를 분리한다

**분류 평가**는 의도·자격·전환의 언어적 해석만 본다. B1/B2/B-fixed에 동일 입력을 주고,
16개 절차·언어별 정확도, 세부 코드 보존, 전환 방향, 잘못된 확신·보류를 측정한다.
v0 결과는 이미 노출된 사후 비교다. 이번 별도 42건도 합성·미검수 라벨이며 법적 정확성 증거가 아니다.
이번 오류를 개발셋으로 승격한다면 새 독립 검증셋을 만들어야 한다.

**검색 평가**는 사람이 고른 정답 구간으로 recall@5와 domain/subcode 오류를 측정한다.
**답변 평가**는 분류 결과를 고정해 검색·답변 자체의 오류를 먼저 분리한 뒤 전체 파이프라인을 평가한다.
첫 60개 공개 합성 QA를 검수 대상으로 제안하고, 이후 기존 v1 300건 계획 안에서 확대한다.
질문 틀·번역·근거 문단을 기준으로 분할하고 test는 코드 고정 전 잠근다.
필수 지표는 claim별 출처 충실도, 인용 위치 일치, 시간 적합성,
서류/기한/수수료 정확성, 충돌 시 보류, 근거 없는 정보 추가 건수다.
고위험 잘못된 단정·도메인 혼합·부모 서류 오상속 0건을 공개 전 필수 조건으로 제안한다.
사람이 검토하지 않은 라벨로 이 조건을 충족했다고 선언하지 않는다.

## 6. 다음 단계 진입 게이트

남은 코드 존재성·전환 표현·여권 갱신 오분류를 해결하고 새 독립 사례로 재검증한다.
F-4 원문 충돌 표시와 최신 법령 본문/서식 검토 경계를 연결한다.
그 뒤 소유자가 공개 자료의 사용 범위와 QA 라벨을 승인해야 한다.
정량 분류 게이트 성공은 학습·운영 배포·자동 병합 승인이 아니다.
