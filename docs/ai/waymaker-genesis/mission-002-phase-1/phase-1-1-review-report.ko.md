## B2 체계 분석과 수리

B2는 16개 절차 catalog의 가장 긴 키워드, 검색 router의 객체×동작 조합, 전환 방향을 사용한다.
등록증이라는 객체 자체는 최초 등록과 재발급을 결정하지 않는다. 여권 재발급과 여권정보 신고도 다르다.
기존 B-fixed는 coarse → fine 역변환으로 카드 재발급, 전자사증, 시간제취업, 조건변경 등의 정보를 잃었다.
대응하는 coarse가 없는 절차도 임의로 상위 절차로 대체했다.

복구 구현은 B2의 저장소 자체 catalog/어휘를 생성물로 공유한다.
Python의 순수 함수가 원문 질의를 직접 판정하고 procedure_fine을 이해 객체와 평가 드라이버로 전달한다.
변환 방향은 fine → coarse이며, 동등한 coarse가 없는 경우 null이다.
평가 데이터·질문 ID·자격별 조건을 분류기에서 읽지 않는다.
기존 legacy task 필드는 호환성을 유지하고, 새 fine이 다른 절차일 때 지식 플랫폼이 coarse 체크리스트를 상속하지 않도록 막는다.
사증발급인정서·전자사증도 답변 guard에서 사증 범위로 처리한다.
배포 문맥 테스트는 #706의 동일 파일과 바이트 단위로 맞춰 충돌 원인을 없앴다.

## 병합·배포 판단과 후속

#706은 검증 범위를 정직하게 표시하는 메타데이터 수리로 한정해 소유자 검토 대상이다.
국적 서식의 확인 범위와 F-4 충돌 표시 후속 계획은 별도 법령 보고서에 남겼다.
#707은 수치상 절차 후퇴를 복구했지만 중요 오류 3건과 독립 검증 오류 2건 때문에 **병합 보류 / NO_GO**를 권고한다.
두 PR은 현재 main을 반영하고 공통 테스트 파일을 동일하게 맞췄다.
실제 리베이스에서 공통 테스트의 충돌이 발생해 #706의 동일한 소켓 차단·503 모의 응답 구현으로 해결했다.
#707은 #706 검토 커밋 위로 리베이스했으며 PR base도 #706 브랜치로 설정한다.
따라서 #707 CI는 법령 수리와 분류 복구를 함께 검사한다. #706 소유자 승인·병합 후 #707을 main으로 재지정해야 한다.
통합 CI의 실제 결과는 두 PR 본문에 기록한다.
소유자의 승인 없이 main 병합·배포하지 않는다.
