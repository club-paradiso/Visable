# PreView by Paradiso — 서비스 계획 (MVP)

> 범위: 2026 외교 공공데이터·AI 활용 경진대회 출품용 독립 MVP. 이 문서는 서비스 경계와 비연동 원칙을 고정한다.

## 1. PreView는 독립 서비스다

- PreView는 `preview.html` + `assets/css/preview.css` + `assets/js/preview/` + `/api/preview/mission`으로 구성된 **독립 라우트·독립 모듈**이다.
- PreView는 Visable의 확장 기능이 아니다. 기존 Visable 검색 페이지, 비자 코드 검색, 사후(입국 후) 체류 안내, Waymaker, F-4 경로 가이드, 국적 페이지, 백엔드 AI 제공자 설정, `visa_data.json`, `doc_master.json`은 수정하지 않았다.
- 제품 경계:
  - **PreView = 입국 전.** 외교부(MOFA)·재외공관·영사 관점의 사전 확인.
  - **Visable = 입국 후.** 체류·정착 행정.

## 2. Visable 비연동은 의도된 결정이다

- 경진대회 지원서가 이미 제출된 상태이므로, 이번 작업에서 PreView를 Visable에 **연결하지 않는다**.
- 사용자에게 보이는 링크·버튼·카드·쿼리 파라미터·CTA 어느 형태로도 PreView ↔ Visable 이동 동선을 만들지 않았다.
- 향후 통합(예: 입국 전 PreView → 입국 후 Visable 인계)은 **대회 심사 이후** 별도 검토 대상이며, 문서로만 남긴다. MVP UI에는 노출하지 않는다.

## 3. PreView가 사용하는 것

1. **외교부 공공데이터 (공공데이터포털)** — 재외공관 정보 OpenAPI(실연동 대상, 백엔드 프록시 경유), 사증 면제협정 체결현황 파일데이터(로컬 스냅샷), 기타 API는 문서화·선택 연동.
2. **재외공관 공식 공개 웹 자료** — overseas.mofa.go.kr 공지·사증 게시판. 수동/오프라인 수집 스크립트(`scripts/preview/collect_mission_notices.mjs`)로만 갱신하며 런타임 크롤링은 없다.
3. **업로드/로컬 사증발급 매뉴얼 참고 레이어** — `scripts/preview/import_visa_issuance_manual.py`가 만든 최소 참고 스냅샷. 매뉴얼은 참고 레이어이며 주 소스가 아니다.
4. **로컬 MVP 샘플 데이터** — API 미연결 시 폴백. 항상 "MVP 샘플 데이터"로 표시된다.

## 4. PreView가 하지 않는 것 (고정 경계)

- 사증 발급 여부·심사 결과를 **예측하지 않는다**.
- 재외공관·외교부의 공식 안내를 **대체하지 않는다**.
- 완전한 요구서류 체크리스트를 **보장하지 않는다**. 체크리스트 카드는 "확인 절차" 안내이지 서류 목록이 아니다.
- 전 세계 공관 실시간 수집·분석을 하지 않는다 (MVP 범위: 베트남·몽골·우즈베키스탄).
- 확인되지 않은 사실은 값 대신 **"공식 원문 확인 필요"** 로 표시한다.

## 5. 키·보안 정책

- 공공데이터포털 서비스키는 백엔드 환경변수로만 다룬다: `MOFA_EMBASSY_SERVICE_KEY` → `PUBLIC_DATA_SERVICE_KEY` → 없으면 안전 폴백 응답.
- 프런트엔드 코드·문서·테스트·로그·응답 어디에도 키를 노출하지 않는다.
- 프런트엔드에 LLM 호출이 없다. 사용자 입력은 렌더링 전 이스케이프(textContent 경유)된다.

## 6. 향후 계획 (대회 심사 이후 검토)

- 재외공관 홈페이지 API(EmbassyHomepageService2) 연동으로 공관 사이트 URL 자동 검증.
- 입국허가요건·안전정보·여행경보 API의 선택 연동(방향성 주의: 한국인 출국 관점 데이터와 혼동 금지).
- 허용된 네트워크에서 mission-notices 수집 스크립트 실행 및 스냅샷 갱신.
- Visable과의 인계 동선 설계 검토 — **심사 이후에만**.
